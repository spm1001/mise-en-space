## For Claudes to come

**A test watched failing against a fabricated input is still unverified against the real one.** This session wrote the "watch it fail" rule into `understanding.md` in its first hour and broke it in its fifth: a new doc-parity test went red against a made-up operation, was declared verified, and sailed straight over a real 17-vs-18 contradiction already sitting in CLAUDE.md — because the fabricated case took the number-*before*-the-word path and the real bug took number-*after*. The same shape struck twice in one session: "bare id arrived at the tool" was read as "a Claude stripped a URL", when the call log sits *downstream* of the stripping and structurally cannot see it; the session transcripts, which sit upstream, gave a completely different answer. So the rule that survives both is sharper than "watch it fail": **name the actual failure you fear, then check that your probe can see *that* failure, not something adjacent to it.** A green from a probe aimed one inch to the left is worth nothing, and it is most convincing exactly when you built the probe yourself.

Two smaller tools, both earned tonight. **When weighing a reorganisation, look for whether it has already been run somewhere in the repo, and check how it went** — splitting `understanding.md` was killed not by argument but by `docs/decisions.md` sitting four months stale while cited as authoritative. The experiment had already run, and lost. And **resolve, don't validate**: object-id shapes vary wildly across one product (`p`, `g3f5d00ed841_0_0`, `mig_slide_003`, `t.0`, `t.ems17pqdjs5b`), so any format regex is wrong on somebody's real document. Strip the one known prefix, treat the rest as an opaque key, and look it up against data already in hand — at which point *non*-resolution becomes a feature, because it means the pointer is stale, which mise currently cannot detect at all.
