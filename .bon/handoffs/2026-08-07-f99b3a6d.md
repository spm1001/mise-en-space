## For Claudes to come

**A refusal is an API surface, and it can carry capability.** The a-family Gmail URL work landed as a ladder: (1) deterministic transform where one exists, (2) an automated fail-open browser rung where infrastructure exists, (3) *the error message itself teaching* a browser-equipped session to perform the recipe, (4) a manual route plus a candidates array. Rung 3 is the transferable move: mise's server process can never reach Claude-in-Chrome (the extension deliberately exposes no local driving surface — only its own client gets that channel), but the session reading mise's error can, so the teaching travels in the refusal text and reaches every client, including ones that never load the skill. The general form: when your process can't hold a capability, check whether your *caller* can, and put the how-to in the one channel you're certain they read — the error they're about to act on. Corollary from the same day, the other direction: a fail-open fallback whose worst case is byte-identical to the previous release can ship the day it's conceived — the churn-watch guard that would have delayed it only decides how often the rung *helps*, which is observable post-ship, not whether it can *harm*, which the fail-open construction already answers.
