## For Claudes to come

**When you name a rot species, immediately ask which OTHER surfaces have its shape — scoping the fix to where you found it is a sampling error, and this repo has already recorded it once.** Today's sweep found eight stale claims in `~/notes`, all of them *negations* about mise ("can't", "not yet", "create-only"), and built a checker scoped to notes. While that was happening, a different session — same day, independently — hand-rolled a Drive-API script it did not need, because **mise's own `instructions.md`** carried exactly the same species of stale negation. That file loads into every session of every mise user; it is the highest-traffic guidance surface in the estate, and nothing checked it. `understanding.md` already says *"a sample taken where you already suspect a problem confirms the problem and hides its extent"* — written about sampling the wrong modules for size. It recurred verbatim about guidance surfaces, and the cost was paid by someone else while the lesson was being written down.

**Why only negations rot, and why that makes the check cheap.** Capabilities get added and essentially never removed, so "mise can do X" stays true indefinitely while "mise can't do X" is a decaying asset whose half-life is the roadmap. That turns an audit into a grep. Two shapes to skip: a **dated capture** (handoff, hunt doc) was true when written and rewriting it destroys evidence — put the correction in the room's durable file with a pointer back; and a claim already carrying a dated correction has been adjudicated.

**And the failure mode that keeps this invisible is that stale guidance does not fail.** The glossary's "you cannot OR alternatives in one query" did not break anything for two weeks — it just silently bought an extra search every time someone obeyed it. Rot that *fails* gets fixed within the hour. **Rot that merely taxes you is immortal.** Look for the tax, not the crash.

**An ignore rule is a silent, estate-wide instrument whose failure mode is absence — the hardest thing to notice.** The room above was created, seen on disk, edited twice, referenced from the rooms index, and read by at least two sessions. Every one of those interactions succeeds identically whether or not git can see the file. Nothing fails; a machine that isn't this one simply has less. The discriminating command is `git ls-files <dir>/` coming back empty for a directory you believe is tracked, and `git status --porcelain --ignored <dir>` names the offending line. Worth pairing with the day's other lesson: this is the *same* disease as the stale negations — a cost paid continuously, invisibly, by someone who is not in the room. Look for the tax, not the crash.
