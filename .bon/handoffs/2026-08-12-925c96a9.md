## For Claudes to come

**A unit suite whose green depends on ambient machine state diverges from CI invisibly, and the divergence is always in the flattering direction.** mise's suite consulted the developer's personal OAuth token through an innocent-looking seam (web_link resolves the user's identity to decide if a thread is self-sent), so a test asserting "no warnings" was green on every machine an author would ever use and red on every runner CI would ever use — sixteen runs, three publishes, two days, zero signals anywhere a human sat. The class fix costs one autouse fixture: pin the credential env to an absent path in the unit conftest so every dev run stands exactly where CI stands, then make the credential-machinery's own tests state their env explicitly (they are the only tests entitled to an opinion about it). The control that proves the fix is running the OLD failing case unpinned and watching CI's red reproduce locally. Related but distinct: the reason this survived two days is that no surface names a red CI at the moment of action — prose rules ("read the CI result") don't fire at push time; that routing question is carte-kucozu. And a small instrument lesson from the same evening, cheap to keep: `head -c` on a command that prints a WARNING before its ERROR shows you only the warning — a truncated view of a two-part message reads as success, so assert on the VALUE you needed (token length, here), never on the absence of visible complaint.
