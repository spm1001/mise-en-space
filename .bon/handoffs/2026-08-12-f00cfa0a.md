## For Claudes to come

**When adding a new way to SELECT an existing mode, put the state behind the mode's existing accessor functions rather than adding a parallel check at each consumer.** The facade's constructor identity (mise-dareti) went into `token_store` as in-process state that `override_path()` and `ambient_mode()` consult — and every downstream gate (guest-mode teaching errors, ambient search narrowing, the mailbox-op refusals, `resolve_token_path`'s guest handling) fired correctly for constructor-selected modes with zero changes, because they were already asking the accessor rather than the env var. The alternative — a third check beside each existing `override_path() is not None` — would have been a scatter of near-misses. Corollary proven the same evening from the consumer side: **a consuming agent's own field notes are a spec surface** — the requirement that hydrated files carry a line-1 `source:` Drive URL came from the Garni spike agent's self-written field handbook, not from any API, doc, or brief, and the example's flatten was silently dropping it until that feedback arrived by accident. When building for an agent consumer, read what the agent tells its successors; the affordances it depends on live there and nowhere else.
