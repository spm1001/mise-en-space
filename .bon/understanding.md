# Understanding — mise-en-space

Mise-en-space is a Google Workspace MCP server that gives Claude access to Drive and Gmail through three verbs: search, fetch, and do. The architecture follows a strict layering — extractors (pure functions), adapters (thin API wrappers), tools (MCP wiring) — and this separation is load-bearing, not cosmetic.

*Compacted 2026-08-02, 14,828 words → ≈8,500. Pre-compaction copy: `git show 7ddbb82:.bon/understanding.md`. The seam is **live invariant vs settled history** — a claim that breaks something if contradicted in code today stays; which suite shipped what, which brief was falsified, which incident got resolved goes to git and the board. If this file passes **~10,000 words**, run the same pass. That threshold is deliberately not 9,000: a trigger that fires on a file you just compacted is a crying-wolf trigger, and those get ignored rather than obeyed. 10,000 leaves roughly a week of runway at recent growth (~1,100 words in the five days before this pass), so when it fires it means something.*

## Mass accumulates where mechanical enforcement can't see

**This is firing again right now, unnoticed — tracked as `mise-nebewe`, which carries the full per-module measurement.** `SERVER_MAX_LINES = 500` in `test_architecture.py` caps **server.py only**; nothing caps anything under `tools/`, `adapters/`, `extractors/` or `resources/`. Measured 2026-08-01: eleven modules exceed that cap, and server.py at 424 is the only file in the repo actually held to it — the largest is `adapters/drive.py` at 1,151. Note the shape of the earlier miss: it sampled the two *gmail* modules, where it already suspected a problem, and so confirmed the problem while hiding its size. **A sample taken where you already suspect a problem confirms the problem and hides its extent.**

The layered code stayed small and pure for a year because `tests/unit/test_architecture.py` policed it, while server.py — outside that test's jurisdiction — quietly grew to 1,318 lines with CLAUDE.md still claiming "server.py just registers tools." **An oversized module in a well-policed codebase signals a jurisdiction gap, not a discipline failure. The fix is extending the rules, not just cleaning the module — the rules make the cleanup self-maintaining.** The jimohe shrink did both. And when writing such rules, prefer **discovery to enumeration**: a glob picks up new files automatically, whereas a hardcoded list is itself the next jurisdiction gap.

## Accept-and-drop is this codebase's characteristic bug (2026-07-27)

All four defects fixed on 2026-07-27 were **one bug wearing four costumes: a value accepted and then silently dropped.** `nextPageToken` was never in the fields mask, so the API never sent it and search capped at 100 forever. A zero-match `replace_text` returned a payload shaped exactly like a successful one. Drive query syntax typed into `query` was keyword-searched — the operator words themselves — and returned confident nonsense. `raw_query` was dropped on the remote path, so a remote caller got an arbitrary slice of the whole Drive presented as their results.

**None had ever been reported in a year of daily use, and the reason is identical in every case: each produced confident, plausible output.** A crash gets reported within the hour; a wrong answer that looks right gets believed and built on. One of these put a false structural claim into a regulatory filing record. So the absence of complaints is not evidence of correctness *for this class* — and the call log is blind to it too, since a silently-capped search logs as a clean `ok`. Only field reports and deliberate probes find these.

Two working rules fall out, and they decided four separate design calls in one day:

- **When a parameter or a signal *can* be ignored, make the ignoring loud — refuse, or cue, but never accept-and-drop.** Refusing Drive syntax in plain `query` rather than searching for the operator words; `NO CHANGE` rather than a success-shaped payload; cueing a URL's `gid` rather than silently scoping the fetch to it; threading `raw_query` into remote rather than letting it evaporate. When you add a parameter, the question is not "does it work?" but "what does the caller see if it silently doesn't?"
- **Assert on the artefact, not the intermediate.** The one defect that shipped that day did so because its test checked the label the code set correctly, while the deposit *filename* — the thing a human actually sees — stayed `search--untitled`. Real output caught it; no test did.

**Refusals that teach get obeyed in seconds; errors that don't cost minutes.** Measured across a week of real usage (2026-08-01): every teaching error mise emitted was followed to the letter within ~30 seconds, while the single bare 404 cost a seven-minute detour by another route. A failure path that names the likely cause and the next move is the cheapest UX surface in this system — cheaper than a feature, and it lands in the one place a caller is guaranteed to read. `mise-tuveda` is its direct descendant.

**The repo-specific verification edge — the part `~/.claude/context/verification.md` cannot hold for you.** `tests/unit/test_edit.py` autouse-stubs `capture_restore_point` to `{}`, so any "no restore point was captured" assertion written there is **vacuous by construction**: it passes whether the production line exists or not. Reverting the production line and confirming red — while a deliberately-added positive control stays green — is what turns a green tick into evidence here. One such revert *itself* silently failed, a regex expecting a space that wasn't in the file, and only `grep -c` on the changed token caught the file sitting unmodified.

**And the red has to be *narrow*: name the test you expect to fail before you run the control.** On 2026-08-02, reverting the Gmail parser to its old second-segment capture reddened exactly one test, and separately disabling the Chat-link guard reddened exactly one different test. That narrowness is the actual evidence — it proves each test tests the thing it names, and that the others are not quietly riding on the same production line. A control that reddens half the file tells you the suite is wired to the code and nothing about which assertion holds which line. And if *more* goes red than you predicted, you have learnt something about your tests rather than about your fix. Cost: revert one line, predict the failure set out loud, run, compare.

**And name the actual failure you fear before trusting a probe, because a probe you built yourself fails most convincingly on the case you invented.** A doc-parity test was watched going red against a *fabricated* operation, declared verified, and sailed over a real op-count contradiction already sitting in CLAUDE.md — the fabricated case took the number-*before*-the-word path, the real bug took number-*after*. Same evening: "a bare id arrived at the tool" was read as "a Claude stripped the URL", when `calls.jsonl` sits **downstream** of the stripping and structurally cannot observe it; the session transcripts, which sit upstream, gave a completely different answer — 38 meaningful decorations destroyed, against the 1 the log could see. Ask which layer your feared failure occurs at, and whether your instrument sits above or below it.

**Generalised once more (2026-08-01, the week-long usage review): where two instruments exist, a verdict from one is a hypothesis.** Pairing `calls.jsonl` with a sweep of 313 session transcripts, every load-bearing single-instrument verdict was wrong or incomplete until the second ran — the log said a 404'd document was silently dropped where the transcript showed recovery seven minutes later; a transcript grep said the mise skill never loaded where exact-match showed it loading twice; a day-old doc reading said Google's preview was gated where the bench handoff recorded it opening mid-session. The corollary caught two of these before they shipped: **a number that looks too clean — 0 of 3, 50 of 50 — indicts the probe's pattern before it describes the world.** Run the known-positive control by default, not on suspicion.

## Which code does your probe actually reach?

**Two divergences live in this repo, they point in opposite directions, and both are silent. Before believing a red or a green from any probe, name the file on disk it imported — `__file__` is one print.**

**Upward, toward published code.** The plugin's `mcpServers` block spawns the server with `--project ${CLAUDE_PLUGIN_ROOT}`, i.e. `~/.claude/plugins/cache/batterie/mise/<version>/`. So `mcp__*` calls always exercise the **published plugin**, never the working tree, and **no session restart changes that** — which makes "smoke through the MCP envelope, then publish" circular by construction: the only envelope available runs the code you were trying to test before shipping it. CLAUDE.md told readers to "smoke-test new features in a fresh session" until 2026-08-03, which cannot work, and the false row survived until someone asked whether reloading actually helped. The break is `scripts/smoke_stdio.py` — same FastMCP stack, same `@mcp.tool` wrapper, same JSON on the wire, just not spawned by Claude Code. It is not a substitute for re-verifying against the installed artefact afterwards; the assembler and the flavour transform sit in between. Corollary, filed as `bds-sawalu` on the **batterie** board: a long-running session stays pinned to whatever plugin version it loaded at start, so an old session runs superseded code while its Claude reasons from a current working tree, with no tell.

**Downward, toward stale code — and this one was still live on 2026-08-03.** `[tool.hatch.build.targets.wheel.force-include]` in `pyproject.toml` lists nine root-tier modules (`models.py`, `validation.py`, `retry.py`, `filters.py`, `html_convert.py`, `markdown_import.py`, `cues_util.py`, `logging_config.py`, `auth.py`) so the wheel is complete for library consumers like glaneur. **force-include has no notion of a source mapping, so it copies those files physically even into the *editable* wheel** — while the layer directories (`adapters/`, `extractors/`, `tools/`, `workspace/`) ride the `.pth` and always resolve live. site-packages precedes the `.pth` path in `sys.path`, so **the copies win** for any process whose `sys.path[0]` isn't the repo root. Measured three ways: a script under `scripts/` → the copy; a script at the repo root → the working tree; a script in `/tmp` → the copy.

**And `uv sync` does not refresh them, which is what makes it durable rather than transient.** Measured: plain `uv sync --all-extras` reported "Checked 92 packages", considered the editable install satisfied, and rebuilt nothing — while the dist-info sat at **1.26.1** against `plugin.json`'s **1.32.1** and the shadowed `validation.py` was **222 changed lines** behind, missing both `diagnose_fetch_404` and `gmail_fragment_segments`. The brief's guessed remedy (`uv sync --reinstall`) is therefore falsified as written: only an explicit `uv sync --reinstall-package mise-en-space` rebuilds. Two things follow. **`smoke_stdio.py` is honest only by accident** — it imports nothing from mise itself, and the `server.py` it spawns sits at the repo root, which is the one location that resolves live. One `from validation import diagnose_fetch_404` in a probe under `scripts/` silently tests July's parser. And **after a reinstall the state is maximally deceptive**: the copies are byte-identical, so any diff-based check passes while the mechanism stays fully intact — a green with a shelf life, same family as the plugin-cache row in `traps.md`. Tracked as `mise-fogede`.

**The companion, and it cost a round on 2026-08-03: a probe's *display* is part of the probe.** `smoke_stdio.py`'s first draft truncated output at 400 characters and printed only the `error` field. Google's 404 URL alone eats ~350, so the teaching text those cases exist to check sat just past the cut — and the one case that genuinely *succeeded* rendered as a blank line, because success has no `error` field. It reported `3/3 passed` while the screen showed what looked like three failures. This is the truncation trap running in reverse: the usual danger is a truncated view read as a complete answer, but a truncated view read as a **null**, and a null read as a **failure**, is just as available and feels even more like diligence. **When a probe surprises you, check the instrument's rendering before you doubt the subject.**

## The generic primitive beats the convenience alias

When mise added `archive`, `star` and `label`, `label` was already the superset — archive is `label("INBOX", remove=True)`, star is `label("STARRED")`. A brief proposed adding `mark_read`, `mark_unread` and `unstar`. The right move was **zero** new operations and better docs, because each new op name costs in three places: the tool description (hard-capped at 2048ch), the dispatch table, and Claude's reasoning about which verb to pick. **Before adding a do() operation, check whether an existing one already handles it with different parameters.** The description ceiling makes this a resource constraint, not an aesthetic.

Three worked examples. **wemuki** landed three missing capabilities — form edit, draft update, trash/discard — as ONE new op with **zero new schema params**, so the signature seam stayed green by construction. **buzafo** closed the whole gather-into-a-folder workflow with *no* new operation, by giving one existing verb one honest flag: `fetch(attachment=…, raw=True)` deposits the attachment's original bytes beside the extraction, so a Gmail-only PDF stops being unreachable. **`do(copy)`** became the 18th op only because nothing stretched to duplication — batch-first, pre-flighting `canCopy` so **`blocked` is reported separately from `failed`**, and refusing folder sources because `files.copy` doesn't recurse and you would get an empty folder that looks like success. Its `blocked` path is unit-tested but **never live-fired**: nothing in this Drive has `canCopy: false`.

Recorded because the sequencing was got wrong out loud — stripping `doc_type='slides'` was announced as a *prerequisite* for copy on the grounds it would free description budget, and it freed **seven characters**. **Measure before asserting a dependency someone is going to plan around.**

When you *do* add one, the op name and count drift more surfaces than CLAUDE.md's recipe lists: `test_dispatch.py` auto-verifies OPERATIONS/DISPATCH sync, but the "N ops: a, b, c…" line lives un-policed in CLAUDE.md, README.md, `DO_DESCRIPTION_FULL`, `docs_do()` and the SKILL.md table.

## The data you need may already be in hand

Before adding an API call — or assuming a scope change — check what the existing fetch already downloads and discards. samono added `last_sender`/`from_me`/`unread_count` plus a snippet to Gmail search for **zero** extra calls: the per-thread fields mask already pulled every message's headers and labelIds, and the old code only read `messages[0]`. Same evening, meduto's invite-state enrichment needed no scope change because `calendar.readonly` already covers `events.list`.

**The write side has the same shape** — three instances in one week: Gmail sendAs signatures read under the already-held `gmail.modify`; the Sheets WRITE scope had been in SCOPES *and the granted token* all along; and `adapters/sheets.py` already carried `update_sheet_values`. Before pricing a feature as "needs a new scope / re-consent / new adapter", run the one-probe checks: **read the granted token's `scopes` array** (not just `oauth_config.py`), grep the adapter for existing helpers, hit the endpoint read-only with the live token.

## The MCP description length ceiling

MCP tool descriptions have a hard ceiling at **2048 characters**. Over it, the description is truncated *and* — the insidious part — the Anthropic API silently drops properties from the tool's JSON schema during `tool_reference` expansion. The loss happens API-side, so CC's permissive schema never gets a chance to help, and the dropped property appears nowhere: not truncated, just absent. `do()` currently declares 26 properties, so going over would silently lose some.

**Fix within our control:** keep descriptions short and put detail in MCP resources (`mise://docs/*`). This is **now mechanically enforced** by `tests/unit/test_tool_description_budget.py`, which carries three asserts: the hard ceiling, a **headroom floor that fails at <100 characters remaining** (so it fires while there is still room to think rather than at the cliff edge), and a check that every op in `DISPATCH` is actually advertised — an undocumented op is unreachable in practice. This section documented the ceiling for months and nothing checked it; adding `do(copy)` took the description to 2036 of 2048, and only a hand measurement caught it. Expect the next person adding an op to meet the headroom assert — that is the design, not a defect. Applies to all batterie MCP servers, not just mise.

## Remote mode architecture

Remote mode was designed around *not touching the fetchers*. The 10+ type-specific fetch functions in `tools/fetch/` are battle-tested and complex, so rather than making them remote-aware, the orchestrators **intercept after the fetch completes**: deposits go to a temp dir, content is read back and included inline, temp dir cleaned up. This post-hoc read-back means all fetchers work unchanged in both modes. Same for search — `SearchResult.to_dict()` already had an inline mode. **Keep the interception in `tools/remote.py`, never inside the fetchers.**

Operation gating is a **whitelist** (`REMOTE_ALLOWED_OPS`), not a blacklist; error messages list only allowed ops, never restricted ones. The tool description adapts per mode via a conditional `description=` on `@mcp.tool()`, which requires `_REMOTE_MODE` to be set **at module load time before decorators run** — for containers use `MISE_REMOTE=1`, because `sys.argv` detection is fragile under process managers.

## Remote deployment path — superseded, don't build it

Explicitly **single-user** (one `token.json`, one `lru_cache(maxsize=1)` per service); multi-tenancy would need per-request credential injection, which is architecturally significant. The hosted path — auth middleware → token management → containerisation (mise-tokiju / winala / sefepo) — is now **superseded rather than merely parked**: mise-mawawa reaches claude.ai and mobile by pointing an ITV-owned OAuth client at Google's managed MCP servers, which is the same goal achieved as configuration with zero infrastructure. Re-open only if that route fails.

Live invariant if a long-running server ever exists again: token refresh needs the token file refreshed AND `clear_service_cache()` called AND services rebuilt — the `lru_cache` bakes a `Credentials` object in at service creation time.

## OAuth and credential architecture

The OAuth client is installed-app type, so the client secret is intentionally distributable and `credentials.json` ships with the repo; **the real secret is the refresh token.** Two GCP projects, two clients: mise's production client lives in ITV's `mit-workspace-mcp-server`, and a second in `planetmodha-tools` backs daemon use under `claude@planetmodha.com`.

**OAuth client User type matters and is invisible from `gcloud`.** The `mit-workspace-mcp-server` consent screen is **Internal**, so any `@itv.com` Workspace user authenticates without verification or a test-user list — bypassing Google's ~6-week verification for sensitive scopes. External-test caps at 100 explicitly-added users; External-published shows a "Google hasn't verified this app" warning. The setting lives only in the console, not the CLI. **For any future ITV-internal MCP, default to Internal.**

**Token storage:** macOS Keychain (`mise-oauth-token`) is the source of truth; `~/.claude/plugins/data/<name>/token.json` is the persistent fallback, and on Linux that file *is* the source of truth (the "Keychain storage failed" line there is benign). The plugin-staging-dir path is ephemeral on Cowork and must never be relied on. The canonical bootstrap is `do(setup_oauth)`, which the friendly error in `adapters/http_client.py` names verbatim when the token is missing — Claude reads the error and calls the remedy.

**Re-auth: revocations are account-level, not a mise bug.** A security event on `sameer.modha@itv.com` (password change, 2SV change, admin sign-out-all) revokes *every* OAuth grant for the account regardless of client — don't hunt for a code cause. **Rejected remedy, recorded so it isn't re-proposed: a dedicated per-mise OAuth client in its own project.** Account-level revocation kills all grants regardless of client, so it would not have protected anything; don't re-propose without a *client-specific* failure. On headless/xrdp tube use the account-agnostic `--code` flow — `uv run python -m auth` (print mode), click the URL in a browser signed into **itv** (the Mac), paste the redirect back. Tube's own xrdp browser is signed into planetmodha and this client is Internal to itv.com, so any browser/listener flow barfs there. Two diagnostic traps: **the call log records `ok:None` for successes** (a populated `result` means it worked), and `localhost:3000` is shared by other tools' OAuth spikes, so check the `client_id` before attributing a `:3000` callback to mise.

**Three fragilities have code answers (zikesa).** Concurrent flows no longer clobber — `.pkce_state.json` keys verifiers by the OAuth `state` param, and a redeem with no findable verifier raises BEFORE calling Google, preserving the single-use code. Stale-server tokens self-heal — `_refresh_or_reload` re-reads the token file when Google refuses the in-memory grant, so **"restart the MCP server after re-auth" is no longer required**. And `can_open_browser()` returns False under `XRDP_SESSION` or `MISE_NO_BROWSER=1` — best-effort only, which is why the explicit override exists: detection cannot know account *suitability*.

## Guest mode — caller-owned credentials (mise-lebapo, 0.7.8; mise-kivane, 0.7.9)

Set `MISE_TOKEN_PATH` and mise runs as a guest: it loads the caller-owned token at that path, never writes back, and persists nothing of its own — no Keychain, no plugin-dir fallback. This is the path for an embedding host that owns its own credential lifecycle.

Three sharp edges shaped it. **Guest tokens are often ADC-shaped**, not mise's own `token.json`, so they're loaded directly rather than assumed into mise's schema. **When the credentials carry a quota project, mise sends `x-goog-user-project`** so billing attributes to the caller's project. And **a guest token may carry no Gmail scope**, so guest mode defaults an omitted `search` source list to `['drive']` — a Gmail search on a Drive-only token would otherwise fail confusingly.

## Google Sheets: the merged-cell trap

Google's Sheets value APIs return *display* data, not *structural* data: merge ranges live in the metadata endpoint (`spreadsheets.get`), not the value endpoint. Fetch values with `FORMATTED_VALUE` and a merged cell returns its value only in the top-left cell; every other cell in the range comes back empty. The fix requests `sheets.merges` in the metadata fields and `_resolve_merges` propagates top-left values post-fetch, horizontal merges included, with a warning cue.

**Sheets editing (lirugi) added no new ops** — the generic-primitive principle. `overwrite` deliberately targets the FIRST grid tab only (clear-then-write CSV, symmetric with create's CSV upload) and warns when other tabs exist; `replace_text` is substring + matchCase + formulas-excluded across all tabs, with an `occurrences_changed` cue. `prepend`/`append` reject, naming the two alternatives. **A future write-to-a-named-tab/range extension should ride A1 notation in an existing param rather than minting a new op** (mise-vadoko), and `adapters/sheets.py` already carries `update_sheet_values` from the charts work — check it before pricing the feature.

## Google Calendar: two traps (2026-07-07)

**The list API hides cancelled events rather than marking them.** `events.list(iCalUID=…)` returns 0 items for a cancelled event unless `showDeleted=true` — absence-of-result is indistinguishable from never-existed. **Any event-state code MUST pass `showDeleted=true`.** Mechanism and probe evidence: `docs/2026-07-07-meduto-invite-event-state.md`.

**Invite-state disclosure is shipped (pinodi), and the cost split is the design.** An invitation email is a frozen snapshot — its ICS says CONFIRMED forever — so mise overlays the LIVE state. **search** carries a free `has_invite` boolean at zero extra calls; the fields mask had to go one level deeper than obvious, because invites nest `text/calendar` inside `multipart/alternative`. **fetch** resolves the UID to `cues.invite_state` plus a STALE SNAPSHOT warning when cancelled, at most two extra calls and only when a thread carries an invite. Two invariants for anyone editing this: the ICS is trivial-filtered out of the user-facing `attachments` list (correct), so `_build_message` keeps it separately on `EmailMessage.calendar_attachments` for the UID lookup; and a guest token may lack calendar scope, so `_enrich_invite_state` swallows any error and returns None — **enrichment never fails the fetch.**

**The cap ate the future, and the fix has three legs that only work together.** Google returns events oldest-first, so a single capped page fills with last week before ever reaching tomorrow. The fix: pass the query to shrink the result set, paginate the full window internally, and use nearest-now selection to decide who survives a genuine overflow (`calendar_truncated` cue). **Any one leg alone re-breaks "is tomorrow's meeting still on?"** Note the downstream cost, now filed as mise-riduka: making the query ride the API `q` param is exactly what makes a query *mandatory*, so clash-checking a diary with no topic term is currently impossible.

## Google Docs: checkbox tick-state is export-only (mise-pirozu, 1.6.0)

Google Docs checkbox **checked-state is not in the Docs API — it is export-only.** `documents.get` returns a byte-identical bullet dict for checked and unchecked rows; a full-JSON deep scan finds no checked field. The `~~` on checked rows in the `text/markdown` export is **synthesised by Google's renderer from the checked bit — it is NOT `textStyle.strikethrough`**, which is FALSE on checked rows, so it cannot be read from the API. The only way to read ticks is a rendered export. (The banked brief guessed "tick == strikethrough" — a wrong mechanism, corrected before building.)

mise's approach: detect a checkbox list, fetch the `text/markdown` export as an oracle, parse markers in document order, and tag each paragraph in place so the pure extractor renders `- [x]`/`- [ ]`. **One extra API call, gated on `is_checkbox_list`, so zero cost otherwise** — the same checkbox-oracle pattern wofomu later reused. Positional alignment is exact on single-tab docs, and a count-mismatch guard renders plain bullets plus a warning — **never a wrong tick**. **Multi-tab tick rendering is untested**: the guard falls back safely on desync, but real multi-tab alignment is unproven.

## Doc comments: read side, write side, and a create/list field trap (mise-cudire, 1.7.0)

mise reads comments (deposited as `comments.md`) and writes them: `do(comment)` opens a NEW unanchored thread, `[agent]`-prefixed; `do(comment_reply)` replies to an existing thread by `comment_id` and can resolve it.

**Drive's comments API has a create/list field asymmetry: `mentionedEmailAddresses` is valid for comments.LIST but 400s on comments.CREATE.** Crucially **the comment is STILL created** — Google persists the resource, then fails serialising the response fields — so a create that 400s can look like a failure while actually succeeding. `_SINGLE_COMMENT_FIELDS` in `adapters/drive.py` deliberately omits it; **don't "tidy" it back to match `COMMENT_FIELDS`.** General lesson: mocked tests can't see field-selection validation, so a do()-op hitting a real Google write endpoint needs a live smoke before you trust it — 16 mocked tests were green and the first real create 400'd.

**Read-side location.** `comments.md` used to be flat and in API order, so a comment anchored on a **heading** — a decision about a whole section — read identically to a comment on one line. `extractors/comments.py` now correlates each anchor against the parsed document, **reorders comments to document order** (unmatched last, with a warning) and renders a `↳` locator, flagging container-anchored ones with `⚠`. Live invariant: **sheets and slides deliberately pass no content and keep the flat API-order render** — location is doc-only, and an inline snapshot enforces it.

**Anchored comment *write* is a platform dead-end, and then turned out to be the wrong goal anyway — don't re-propose either half.** A real comment's `anchor` is an opaque `kix.*` ID minted by the Docs *editor*, and `comments.create` **stores whatever string you send verbatim and never resolves it**, so a 200 plus an id proves nothing; five attempts across four formats all read back `quotedFileContent=''`. Then the reframe dissolved the need: the triage loop wants **replies to the human's threads**, and a reply attaches by `comment_id` to a comment that already carries the human's editor-minted anchor — **so the reply inherits the anchor for free**. The round-trip is already complete and shipped.

## Google Docs: suggested edits (mise-wofomu, suite 1.19.0)

`fetch(suggestions=)` closes the silent-loss gap on Docs carrying suggested edits. API mechanics, bought with live probes: `documents.get` defaults to an inline mash for editors — every suggestion-tagged textRun carries `suggestedInsertionIds`/`suggestedDeletionIds`, and **the insert and delete halves of a *replace* SHARE one suggestion id**, which is how markup mode pairs them. `PREVIEW_SUGGESTIONS_ACCEPTED` returns the suggester's intended text server-side; `PREVIEW_WITHOUT_SUGGESTIONS` the original. **The API never exposes *who* made a suggestion.**

Modes: `accepted` (default), `original`, `markup` (`{++ins++}[s1]`/`{--del--}[s1]`, shared `[sN]` = one replace). First call is always SUGGESTIONS_INLINE (countable); preview modes cost a second `documents.get` only when suggestions exist — the checkbox-oracle gating pattern again. Two honest edges: **counting is text-level only**, so a doc with only structural suggestions fetches without the warning; and view-only access requesting SUGGESTIONS_INLINE on someone else's doc is **untested** — if a view-only fetch errors on the first call, that is where to look.

## Drive revisions: no names, no pins, but recoverable content (mise-cizuzi, suite 1.20.0)

**The Revision resource on native Docs has no `name` field, and `keepForever` is binary-content-only — both accept the write with HTTP 200 and silently ignore it.** A green response proves nothing; verify by read-back. This falsified cizuzi's briefed design ("named restore points") in three API calls. But per-revision `exportLinks` genuinely work — they 307-redirect to googleusercontent with an embedded token — so historical content **is** recoverable even though versions cannot be pinned or named.

The shipped design pivoted accordingly: every mutating do() op on a Google Doc captures the head revision BEFORE editing and returns `cues.restore_point {revision_id, modified_time}`, the precise Version-history entry to revert to; `overwrite` additionally posts an `[agent]` comment naming it (`restore_comment=False` to suppress). **Capture is best-effort — failure warns, never blocks the edit.**

## Gmail drafts: N objects per thread, ONE rendered (mise-sasivo, suite 1.21.0)

Gmail legally holds **N draft objects per thread while conversation view renders exactly ONE inline** — so a silently created second draft hides exactly where the user hits Send (the Drafts *list* shows a row per object, hence "two red Drafts, one visible"). `reply_draft` therefore lists the thread's drafts first and **REFUSES** when one exists, naming its id and snippet — update it via `draft(file_id=…)` or pass `supersede=True` to discard-then-create. The check is **fail-open with a warning cue** (a listing hiccup never blocks the draft); `supersede` is rejected in remote mode, because drafts.delete is permanent and the discarded draft may carry a human's hand-edited words — **the refusal's snippet exists so the caller checks whose words they are first.**

Adapter trap: **`drafts.list` under a fields mask returns a ZERO-LENGTH body (not `{}`) when there are no drafts** — it will crash a naive `orjson.loads`; `list_thread_drafts` parses raw bytes.

## Drive search: pagination, raw query, and AND semantics (suite 1.24.0–1.25.0, 2026-07-27)

**Drive search silently capped at 100 results for a year, and the root cause is the instructive part: `nextPageToken` was never listed in `SEARCH_RESULT_FIELDS`, so the API never sent it.** The signal wasn't ignored by buggy code — it was never requested, which is why a year of capped searches produced nothing to notice. Gmail had paginated correctly the whole time, so the two sources disagreed silently. `search_files` now pages to `max_results` behind a 10-page / 1,000-result guard.

**Two cues answer different questions and both can fire — don't collapse them.** `drive_truncated` = *fetched vs matched*, and it is **exact**, derived from a surviving page token, so it distinguishes 25-of-25 from 25-of-1292. `preview_partial` = *shown vs fetched*, and fires on every source. Open edge: a 1,000-result deposit is a large JSON (probe runs wrote 2.4 MB).

**`raw_query=` passes Drive's own query language through unescaped** — `or`, `not`, `name contains`, `modifiedTime >`, `'x' in owners`. Drive-only, mutually exclusive with `query`, composes with `type`/`folder_id`, `trashed = false` still ANDed on. Its twin is `looks_like_drive_query()`, which **refuses** operator-shaped input typed into plain `query`, because that used to keyword-search the operator *words* and return confident nonsense. **`raw_query` is unescaped by design** — correct for single-user stdio against your own Drive; if mise ever grows an untrusted caller, this is the first thing to revisit.

**Plain `query` is AND across every word — proved by control, not documentation.** A nonsense token returned 0 against a query that otherwise matched hundreds. This *inverts* the standard advice: when a search returns nothing, the fix is usually to **drop terms**, not to be more specific.

**The URL-decoration survey yielded a reusable rule: resolve, don't validate.** Five decorations — `?gid`, `?tab`, `#heading`, `#slide`, `?disco` — all resolve against data mise already downloads, for zero extra API calls (findings and plan on mise-dogape). Object-id shapes vary wildly inside one product (`p`, `g3f5d00ed841_0_0`, `mig_slide_003`, `t.0`, `t.ems17pqdjs5b`), so **any format regex is wrong on somebody's real document.** Strip the one known prefix, treat the remainder as an opaque key, look it up against data in hand — at which point *non*-resolution becomes a feature, because it means the pointer is stale, which mise currently cannot detect at all. This batch is the repo's strongest case for **probe before building**: four live probes ran before any code and changed the design twice.

## Build flavours: full vs slim (mise-hibere, 0.7.9)

Mise ships in two shapes from one codebase. The **full** build (dev, CI, the marketplace plugin) carries local extraction — `markitdown[pdf]` + `pdf2image` — for fast local PDF text, HTML→markdown and PDF page thumbnails. The **slim** build (what Cornichon vendors) installs plain core: `markitdown` is absent, so `adapters/pdf.py` degrades to Drive server-side conversion, `html_convert.py` to tag-stripping, and PDF thumbnails are skipped. Image fetch still works because `pillow` is core.

**The mechanism is the load-bearing part: the "full" choice rides in the *spawn* command (`uv run --extra extraction`), not the install command.** You can't make an extra on-by-default, so "default install = slim, full opts in" is forced; routing the opt-in through plugin.json means zero estate-wide install-command churn, and the assembler vendors plugin.json so the arg travels. **Watch that arg — if `--extra extraction` is ever dropped, every plugin and Cowork user silently goes slim.**

Two consequences: run the test suite with `--all-extras`, because PDF-extraction tests assume markitdown is present and fail in a slim env; and the slim PDF→Drive fallback needs Drive **write** scope (it uploads to convert), fine for own-Drive PDFs but it would break under a read-only guest token. **Direction of conversion maps to flavour:** HTML→markdown is extraction-extra, markdown→HTML had to go in **core**, because `draft`/`reply_draft` are remote-safe ops that must render GFM in every flavour. Rule of thumb: anything a remote-safe op needs is core; local fast-path extraction is the extra.

What made slim cheap rather than crippling was profiling what the weight actually buys. The 67M monster was onnxruntime, pulled in by magika — markitdown's ML byte-level file-type *sniffer*, which mise never needs because it routes by Drive MIME metadata rather than sniffing bytes. **Before declaring a dependency load-bearing, check whether its expensive part answers a question you have already answered another way.**

## Identity flavours: mise (ITV) vs mise-home (Planet Modha) — a SECOND flavour axis (mise-tatego, 2026-07-12)

Distinct from build flavours above (full/slim = *extraction extras*); this axis is *identity/credential*. Mise ships as two published plugins from one source — **`mise`** (work, `mit-workspace-mcp-server`, `sameer.modha@itv.com`) and **`mise-home`** (personal, `planetmodha-workspace-mcp`). Only these two will ever exist.

**Build topology, three repos, and it is easy to get lost:** `spm1001/batterie-de-savoir` is the suite *source*; `spm1001/batterie` is a *separate, generated* marketplace holding `assemble.sh`; `spm1001/batterie-home` is a *private, generated* marketplace carrying only `mise-home`. Every file in the generated ones is output — **never hand-edit.**

**The flavour transform** (`make-mise-flavour.sh`) is a guarded string substitution over the vendored copy: data-dir, keychain service, rules filename, plugin `name`/`displayName`/`identity`, the mcpServers key, and the skill's `mcp__mise__`→`mcp__<name>__` tool refs — then swaps `credentials.json` and runs a `scan` guard that **fails the build if any ITV-identifying string leaks through**. Why substitution rather than a runtime env axis: **the SessionStart hooks carry hardcoded identity strings and run in the session env, so an `mcpServers.env` block cannot reach them.**

**The gap it exists to close:** the transform differentiates every *plumbing* surface, but left every *model-facing* surface byte-identical — so two same-named "mise" tools coexisted in one session and an unauthenticated flavour's correct no-token warning read as "the *other* mise is broken." The fix is a symmetric `identity` label carried in the **source** `plugin.json`, not in `assemble.sh` — because `plugin.json` is drift-exempt from the ratchet and the assembler vendors mise in a *generic* loop, so special-casing it there would rot. A **field-specific** guard asserts the swap landed, rather than a file scan, so the hook's legitimate sibling reference to "ITV (itv.com)" isn't a false leak. `ensure-mise.sh` reads `identity` once and drives the warning, the rules-shard filename and the skill description marker. A per-result "acting as" cue was **deliberately declined**.

**Per-flavour token stores never cross:** each flavour's `TOKEN_FILE` is `~/.claude/plugins/data/<name>/token.json`, so authenticating one does nothing for the other.

**The harness names MCP tools by INSTALL METHOD, not by server alone — so there are two legitimate prefixes per flavour and the transform rewrites both** (measured 2026-08-03, mise-soheka). A plugin install yields `mcp__plugin_<plugin-name>_<mcpServers-key>__<tool>`; a bare MCP server in settings or `.mcp.json` yields `mcp__<key>__<tool>`. Observed across four independent plugin servers: `mcp__plugin_mise_mise__*`, `mcp__plugin_sonnette_sonnette__*`, `mcp__plugin_episodic-memory_episodic-memory__*` (**hyphens are preserved, there is no sanitisation**) and `mcp__plugin_compound-engineering_context7__*` — that last one is decisive, because plugin name and server key differ, proving they are two independent fields rather than one doubled name. So mise-home is `mcp__plugin_mise-home_mise-home__*` by derivation, not probe. **The consequence for guidance: `mcp__mise__*` is not a wrong name, it is the right name for a different install method**, which is why the shard and the skill now name the plugin form and mention the bare form rather than hardcoding either. mise emitted `mcp__mise__*` from 2026-01-31 to 2026-03-17 (CC 2.1.77) and `mcp__plugin_mise_mise__*` from 2026-03-18 (CC 2.1.79) — a clean same-day switchover with no overlap.

Two edges worth keeping. **A grep of your own tool list for a hardcoded prefix is a silent zero** — the shard told every session `mcp__mise__*` for four and a half months, and across 6,002 transcripts exactly two calls hit the dead name, both getting a loud `No such tool available`; one recovered in six seconds, one abandoned the call and went to reading source instead. **And `allowed-tools` is a permission *pre-approval*, not a restriction** (`disallowed-tools` is the restricting field), so the skill's non-matching glob withheld nothing — it simply granted nothing, a permission rule that silently guards nothing. It was inert on tube only because `settings.json` already allowed the live prefix; on a machine without that line every mise call in a skill-invoking turn would have prompted.

## Code patterns

- **Folder cues** in `tools/create.py` use a shared `_resolve_folder_cues()` helper; **PDF rendering** is platform-adaptive (CoreGraphics on macOS, pdf2image/poppler on Linux — and poppler's absence is a silent thumbnail failure, mise-releko).
- `get_deposit_folder` **wipes on re-call** — never call it twice for the same folder mid-operation. This is a real retry hazard: don't add automatic HTTP-level retry to fetch in remote mode.
- `MiseSyncClient.upload_multipart()` boundary is UUID-based, because binary uploads could contain static boundaries.
- google-auth `Credentials.valid` only checks local `expiry` — the httpx client retries once on 401 with forced refresh.
- **Heading extraction** suppresses the blockquote prefix when a heading prefix is already present, preventing `> ##` for indented headings.
- **Shadow field masks.** When an adapter defines a constant for API field selection but the call site uses a locally-defined string, mocked tests pass because mocks return whatever you tell them regardless of which fields were requested. The `is_unread` bug was this. **Guard by testing the mask itself (`assert "labelIds" in fields`), not just downstream logic** — any time you see a fields/projection mask in an adapter, verify the call site uses the constant.
- **Driving `run_operation` directly (smoke scripts) requires the FULL param dict** — the DISPATCH lambdas use `p["key"]` access and server.py always passes every key, so a partial dict raises KeyError'd INTERNAL errors that look like handler bugs.
- **An idempotency gate keys on its OWN state, not a proxy.** `configure_call_logging`'s early-return was `if _calls_logger.handlers: return` — a fail-open proxy conflating "any handler exists" with "our file handler is wired." It worked until pytest 9.1's logging plugin injected capture handlers onto the logger, tripping the early-return so the call log never got its `RotatingFileHandler`. **When an "already done?" check tests a proxy for the real condition, check the real condition.**

## Field reports outrank synthetic tests

When a field report names the file, the lines, the root cause and a fix sketch, it is grounded in real reproduction; existing unit tests are often snapshots of synthetic shapes from one fixture. **If the brief's recommended fix breaks a test, read the test before hunting for an alternative** — usually the test asserts a *more aggressive* version of "correct" and the field report has just shown that aggression eats real content. Update the test to the new contract rather than finding a clever fix that preserves the test's shape. Worked case: a brief said "walk backwards" for signature stripping; that broke a test, so a proximity-window alternative was tried, which preserved the test but didn't fix the standalone-message case. Walking backwards and updating the test was right all along.

**Companion discipline — probe the mechanism before building.** Both build briefs in the 2026-07-22 session were right about the *problem* and wrong or unproven about the *mechanism*: cizuzi's "named revisions" design was falsified in three API calls. A cheap probe — three or four API calls against a purpose-built throwaway fixture — beats any amount of design-from-docs, and the fixture keeps paying: one Firework-lyrics doc served as repro, test fixture, demo stage and smoke target across three releases. Build the tiny fixture; probe the mechanism; only then design.

## MCP Resources: what they're for

Mise ships eight FastMCP Resources — six static docs (`mise://docs/*`), one live API call (`mise://gmail/labels`), one parameterised template (`mise://tools/{tool_name}`). Two empirical behaviours: **parameterised templates are invisible to discovery** (listing returns only the seven concrete URIs, though a hand-constructed URI resolves fine), and **content comes back inline**, so cold-fetching content via a Resource dumps the whole payload into context.

**The right division of labour:** Resources for small live introspection (labels, drafts, quota); `fetch` for content acquisition; native filesystem read for steady state. The URI scheme is **not** load-bearing. Generalisable: when a layer X exists "because of Y" and Y gets cut, audit X — it usually goes too.

## Gmail: the code's actual shape

*The paragraphs below are the only place this file describes how the Gmail path actually works, and every claim still matches code. They spent months buried under a "Current state (June 2026)" heading whose own caveat told readers to discount them — rescued 2026-08-02. For what shipped when, read `git log` and the board.*

**Signature stripping walks *backwards* from end-of-body**, because forward-walking false-positived on benign short text where URL density bled up from quoted Outlook replies below. `strip_signature_and_quotes` returns `(body, warnings)`. **Apple-Mail-style bare-name lines survive stripping by design** — under-stripping is safer than eating content, so "mise didn't strip Alice's name" is the trade, not a bug.

**The catastrophic-strip revert (rejula) is the guard that matters, and its dual condition is deliberate.** A >80% warning wasn't enough: a strip could eat the whole message and merely flag it. mise now **reverts to the pre-strip body** when a strip BOTH keeps <35% of the original AND removes >1000 chars absolute — mechanism-agnostic, so a legitimate compact-sig strip on a short reply is protected by the absolute floor while a body-eater on a long message is caught by the ratio. The culprit was `_strip_trailing_contact_block`; talon was exonerated, it only scans the last 11 lines. **The call log is blind to this whole class** — a content-eating strip logs as a clean `ok`. Stock-taking finds the *fumbles*; only field reports find the *silent* failures.

**Two header-level traps, both live.** `_parse_headers` canonicalises header-name case (RFC 5322 — Outlook emits `CC:`, which an earlier case-sensitive filter silently dropped, starving cc lists AND participants), and `do_reply_draft` passes `current_user_email()` into reply_all inference so self-exclusion actually fires. Participants walk From+To+Cc+Bcc across all messages (`_extract_participants`, deduped on canonical email with the best display form), and **Outlook's `application/octet-stream` mis-tagging is recovered by filename extension** (`_resolve_attachment_mime`) on both the attachment-fetch and eager thread-fetch paths. .docx fetches warn when Word markup was flattened: `extractors/docx_markup.py` counts w:ins/w:del/comments/inline-images by **regex on bytes, not an XML parse — email attachments are untrusted input and regex can't be entity-bombed**.

**File layout after the wugehi split:** `tools/fetch/gmail.py` holds two orchestrators; the three concerns live in siblings — `gmail_participants.py`, `gmail_exfil.py`, `gmail_attachments.py`. `classify_attachment()` in gmail_attachments is the **single source of MIME→category dispatch** (it was triplicated and drifting). Test patch targets for the moved helpers point at `tools.fetch.gmail_attachments.*`; the `tools.fetch` facade keeps all public imports stable.

**Forms, and the recipe for a new content type.** `do(create, doc_type='form')` is structurally unlike every other create path — two API calls on `forms.googleapis.com` rather than Drive's `files().create()` with media upload — so it branches early in `do_create`, before any Drive-centric logic. Two live gotchas: **item titles cannot contain newlines** (400 "Displayed text cannot contain newlines"; `_split_title()` splits multi-line YAML block scalars into title + description), and form descriptions render as plain text, so bullets appear literally. The recipe a new content type follows: add scope, adapter, extractor, wire the elif in the router, update the three MCP resource strings and this file. That last step is easy to forget **because omission causes no test failure** — it just leaves future Claudes unaware the capability exists.

**Google API error bodies are lost in `raise_for_status()`** — it throws before the body can be read, so bypass with a raw `httpx.Client` call when debugging. Tracked as mise-wipopo.

## Cowork & Desktop integration

**Cowork is Claude Code in a VM with `~/.claude/` swapped for a session-scoped temp dir.** An uploaded plugin is staged into `CLAUDE_CONFIG_DIR` and CC's standard machinery does the rest — plugin loader, `SessionStart` hooks, stdio MCP spawn — all on the **Mac side**, unchanged from native CC. ## UX patterns: friendly error wrapper

When an external dependency (OAuth token) is missing, the tool's error response includes a *concrete in-app remediation pointer* — not a CLI command, but the name of another tool the same Claude can invoke. The remediation tool spawns a detached subprocess so the MCP call returns immediately with a URL inline as fallback. The data self-discloses; Claude reads the error, finds the remedy verbatim, calls it.

This pattern showed up twice in the 2026-05-04 install sweep: (1) `mise.do(operation="setup_oauth")` invoked because the error message named it, and (2) the multi-Workspace-connector ambiguity that became the `cues._identity` polish bon. **General principle:** prefer self-disclosing data over instructional copy. Skill copy may not be read; data attached to a response always is.

Google now runs its own managed MCP servers, one per product, at `{gmail,drive,docs,sheets,slides,calendar,chat}mcp.googleapis.com/mcp/v1`, with a cross-corpus `workspacemcp.googleapis.com/mcp/v1` on top — Cloud Next '26 developer preview, auth terminated by `accounts.google.com`, RFC 9728 metadata live. Anthropic's built-in Gmail and Calendar connectors were **re-platformed onto them**: `gmail.mcp.claude.com` and `gcal.mcp.claude.com` are now dead hostnames (CNAME residue, TLS unmapped, verified against a live control), while `microsoft365.mcp.claude.com` still serves — so the Anthropic-proxy fleet persists only where the provider has no managed MCP of its own.

**The consequence that matters: Google's servers accept ANY OAuth client.** The ITV gate on the built-in connector is that it authenticates with *Anthropic's* client, which ITV app access control blocks — but an ITV-Internal client, which is mise's exact trick, pointed at Google's hosted servers is a zero-infrastructure sanctioned path. That is what makes mise-mawawa possible as configuration rather than hosting, and it is why the remote-deployment path above is superseded.

Measured strengths and weaknesses, from the bench (`docs/2026-08-01-google-mcp-spike.md`). **They win** server-side relevance ranking of Gmail — the one capability mise structurally cannot build, because rankers live with indexes and the Gmail API exports a filter with no ordering parameter — and calendar recall, 4/4 against mise's 0/4 on the ±7d window. **Mise wins** payload economics (2KB against 205–264KB), metadata (their results carry no timestamps, labels or unread state), and honesty. So the evidenced design is a hybrid: their ranker for candidate *discovery* inside mise's envelope, hydrated with mise's own metadata and deposited as usual (mise-gofuvu).

**Their surface measurably accepts-and-drops, so consume it the way this repo would want to be consumed.** `pageSize` is ignored, pagination is phantom, `includeComments` is a no-op, and their `update_values` writes no `chipRuns` and no `textFormatRuns` — so rich-text and smart-chip writing does not exist there either, and routing Sheets link work through them does not cover what mise-bazuvo actually wants. Re-derive rather than trust: count their items yourself, stamp your own timestamps, hydrate metadata via mise's own APIs, and cue any divergence between their contract and their behaviour. Exercise every parameter with an observable-effect case before relying on it, and re-probe on preview churn. Pre-GA terms forbid customer-facing use; personal and team use is fine.

## The release ratchet — how not to wedge the marketplace

Mise reaches users through the single assembled marketplace `spm1001/batterie`, which vendors mise's **full runtime source** because mise declares `mcpServers`. The vendor boundary is **wider than runtime code**: `CLAUDE.md`, `README.md`, `CHANGELOG.md`, `skills/`, `pyproject.toml`, `uv.lock`, `instructions.md`, `credentials.json`, `hooks/` and `apps-script/` all ride along. **The ONLY free-to-commit-unbumped trees are `tests/`, `docs/` and `.bon/`** — a "docs fix" to CLAUDE.md is ship-coupled, not free. Versioning is suite-managed, so mise's own `plugin.json` version is local-dev-only: release via `/batterie:publish`, never hand-bump and never hand-run the assemble.

**The ratchet fires on content-changed-at-unchanged-version, and it has two triggers.** The obvious one is a hand edit to vendored content. The other: **a Dependabot merge is a vendored-content change**, because `pyproject.toml` and `uv.lock` are vendored — so publish a patch after one merges rather than leaving it for the 07:00 UTC cron. The tell before it bites is shipped `plugins/mise/pyproject.toml` diverging from `main`.

Two reflexes from the day the shared bus went down. **(1) When a marketplace publish fails, check whether a *sibling* repo is the cause before hunting in your own** — one unbumped edit elsewhere blocked every plugin for hours. **(2) A bump clears the ratchet regardless of which content changed, so the fix working does not validate the causal story.** A wrong cause propagated through three artefacts that day before substrate-checking corrected it.
