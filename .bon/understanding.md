# Understanding — mise-en-space

Mise-en-space is a Google Workspace MCP server that gives Claude access to Drive and Gmail through three verbs: search, fetch, and do. The architecture follows a strict layering — extractors (pure functions), adapters (thin API wrappers), tools (MCP wiring) — and this separation is load-bearing, not cosmetic.

*Compacted 2026-08-02 (14,828 → ≈8,500, `git show 7ddbb82:`) and again 2026-08-04 (10,034 → ≈10,400, `git show 207d9c4:`). The seam is **live invariant vs settled history** — a claim that breaks something if contradicted in code today stays; which suite shipped what, which brief was falsified, which incident got resolved goes to git and the board. If this file passes **~10,000 words**, run the same pass. The threshold is deliberately not 9,000: a trigger that fires on a file you just compacted gets ignored rather than obeyed.*

*Read the second pass as a warning about the instrument, not a success. It cut ~1,600 words of settled history and duplication and added ~1,600 of new durable material, landing where it started — so **the threshold measures growth, and a pass that merely holds the line is the expected outcome on a busy day, not a failure.** What it cannot tell you is whether the file is still *readable*, which is the property Sameer actually judged when he declined the last compaction on the grounds the file wasn't unwieldy. If a future pass finds itself shaving good prose to hit the number, stop: the number is a smoke alarm, not a budget.*

## Mass accumulates where mechanical enforcement can't see

The layered code stayed small and pure for a year because `tests/unit/test_architecture.py` policed it, while server.py — outside that test's jurisdiction — quietly grew to 1,318 lines with CLAUDE.md still claiming "server.py just registers tools." **An oversized module in a well-policed codebase signals a jurisdiction gap, not a discipline failure. The fix is extending the rules, not just cleaning the module — the rules make the cleanup self-maintaining.** And when writing such rules, prefer **discovery to enumeration**: a glob picks up new files automatically, whereas a hardcoded list is itself the next jurisdiction gap.

**The gap is now closed and the enforcement's live shape is a ratchet, not a cap.** Every `*.py` under the five layer directories is held to 500 lines, discovered by glob; the eleven modules already over when the rule landed are frozen at their then-size in `_LEGACY_SIZE_BASELINE`, may only shrink, and a shrink of more than 50 lines fails until the number is lowered — so the debt cannot grow back. **Its weak point is social, not technical:** anyone tripping it can raise their own baseline number, at which point the ratchet becomes permission. The docstring asks for that raise to be argued in the commit message, which is a convention and not enforceable further. Splitting the eleven is separate, unstarted work.

**Treat the ratchet as a design force, not merely a guard — let it place your code (2026-08-09).** The Gmail `web_link` work found both of its natural emit sites frozen at zero headroom (`adapters/gmail.py` 1065/1066, `tools/fetch/gmail.py` 695/695), and the pressure produced a better layout than freedom would have: the token encoder went to `validation.py` beside its own inverse, the fetch-side logic went to the `gmail_ids` sibling as a single helper so the frozen call site paid three lines, and the search side computes at format time from fields already on the dataclass — zero adapter change. One argued baseline raise (695→701, reason in the comment) covered the lines that genuinely had to sit in the frozen file. **When the ratchet blocks you, ask "which unfrozen sibling owns this logic?" before "how much do I raise the number?"**

**The freeze-and-ratchet move is now the house pattern for any standing debt nobody can verify by hand — three instances strong (2026-08-10).** Module sizes (`_LEGACY_SIZE_BASELINE`), guidance negations (`test_guidance_freshness.py`), and mypy errors (`test_mypy_baseline.py`, mise-bunuvu) all follow the same shape: freeze the present in an enrolled, reasoned baseline, police the delta in BOTH directions (new debt reds; banked debt that's been paid also reds until the entry is lowered), and make every red teach its own adjudication in the failure message. When the next hand-counted, drift-prone number appears in a doc, reach for this before reaching for prose.

Two method residues from finding it. **A sample taken where you already suspect a problem confirms the problem and hides its extent** — the earlier miss sampled the two *gmail* modules, where a problem was already suspected, and so never saw that `adapters/drive.py` was the real outlier at 1,151 lines. And a rule written against *content drift* would have been red during ordinary work and rightly ignored; what made `TestProbeScriptsSeeTheWorkingTree` enforceable was targeting the thing that makes drift **harmless** (import ordering) rather than the drift itself. **Prefer the invariant that survives normal work.**

## Accept-and-drop is this codebase's characteristic bug (2026-07-27)

All four defects fixed on 2026-07-27 were **one bug wearing four costumes: a value accepted and then silently dropped.** `nextPageToken` was never in the fields mask, so the API never sent it and search capped at 100 forever. A zero-match `replace_text` returned a payload shaped exactly like a successful one. Drive query syntax typed into `query` was keyword-searched — the operator words themselves — and returned confident nonsense. `raw_query` was dropped on the remote path, so a remote caller got an arbitrary slice of the whole Drive presented as their results.

**None had ever been reported in a year of daily use, and the reason is identical in every case: each produced confident, plausible output.** A crash gets reported within the hour; a wrong answer that looks right gets believed and built on. One of these put a false structural claim into a regulatory filing record. So the absence of complaints is not evidence of correctness *for this class* — and the call log is blind to it too, since a silently-capped search logs as a clean `ok`. Only field reports and deliberate probes find these.

Two working rules fall out, and they decided four separate design calls in one day:

- **When a parameter or a signal *can* be ignored, make the ignoring loud — refuse, or cue, but never accept-and-drop.** Refusing Drive syntax in plain `query` rather than searching for the operator words; `NO CHANGE` rather than a success-shaped payload; cueing a URL's `gid` rather than silently scoping the fetch to it; threading `raw_query` into remote rather than letting it evaporate. When you add a parameter, the question is not "does it work?" but "what does the caller see if it silently doesn't?"
- **Assert on the artefact, not the intermediate.** The one defect that shipped that day did so because its test checked the label the code set correctly, while the deposit *filename* — the thing a human actually sees — stayed `search--untitled`. Real output caught it; no test did.

**The 2026-08-08 chip probe completed the family: accept-and-drop has two siblings, accept-and-IGNORE and accept-and-ENRICH, and nothing in the HTTP 200 distinguishes any of the three.** Drive revision names and keepForever are accepted-and-ignored; a chip write is accepted-and-*enriched* (write `@` + chipRuns, read back the target's live title standing where your value was). So on Google write surfaces the read-back is a design input, not a verification formality — three probes in one evening (FY2025 corpus, multi-tab refusal, chip enrichment) each **changed** a design rather than confirming it, and the enrichment fact alone is what flipped chips from auto to opt-in.

**Refusals that teach get obeyed in seconds; errors that don't cost minutes.** Measured across a week of real usage (2026-08-01): every teaching error mise emitted was followed to the letter within ~30 seconds, while the single bare 404 cost a seven-minute detour by another route. A failure path that names the likely cause and the next move is the cheapest UX surface in this system — cheaper than a feature, and it lands in the one place a caller is guaranteed to read. `mise-tuveda` is its direct descendant.

**The repo-specific verification edge — the part `~/.claude/context/verification.md` cannot hold for you.** `tests/unit/test_edit.py` autouse-stubs `capture_restore_point` to `{}`, so any "no restore point was captured" assertion written there is **vacuous by construction**: it passes whether the production line exists or not. Reverting the production line and confirming red — while a deliberately-added positive control stays green — is what turns a green tick into evidence here. One such revert *itself* silently failed, a regex expecting a space that wasn't in the file, and only `grep -c` on the changed token caught the file sitting unmodified.

**And the red has to be *narrow*: name the test you expect to fail before you run the control.** Reverting the Gmail parser to its old second-segment capture reddened exactly one test; separately disabling the Chat-link guard reddened exactly one different test. That narrowness is the evidence — it proves each test holds the line it names rather than riding on a shared one. If *more* goes red than you predicted, you have learnt something about your tests rather than about your fix.

**Controls that mutate files: stage everything BEFORE the first control, then restore with `git checkout -- <path>` (2026-08-09).** Unstaged, checkout fails both ways silently-ish: on untracked files it errors and the control mutations accumulate across rounds; on tracked files it reverts the WHOLE file to HEAD/index, eating unstaged real work along with the control (one revert ate create.py's chip wiring, re-applied from context). The accumulated reds stayed interpretable only because each control added exactly its one predicted failure — diverse narrow predictions kept a corrupted harness readable. Staged-first, the same loop ran clean. Edit-tool reverts are the alternative when staging is premature. **And the staged index is a loaded gun for the next commit: `git commit` without path arguments commits the whole index** — which bites precisely in this stage-everything workflow, where staging was a safety step and the sweep arrives later wearing an unrelated commit message (2026-08-17). After a staged-first control round, commit with explicit paths.

**This repo has exactly two instruments for questions about caller behaviour, and picking the wrong one is the recurring error: `calls.jsonl` sits DOWNSTREAM of the caller, session transcripts sit upstream.** So the log can never answer "did a Claude strip this URL before calling?" — it records only what arrived. Asked properly of the transcripts, the answer was 38 meaningful decorations destroyed against the 1 the log could see. Generalised from the week-long usage review: **where two instruments exist, a verdict from one is a hypothesis** — every load-bearing single-instrument verdict there was wrong or incomplete until the second ran. **Ask which layer your feared failure occurs at, and whether your instrument sits above or below it**; and treat a number that looks too clean — 0 of 3, 50 of 50 — as an indictment of the probe's pattern before a description of the world.

## A green suite is scoped by the door the tests enter through (2026-08-10)

mise has exactly three consumer doors: the **MCP envelope** (Claude sessions over stdio), the **installed wheel** (glaneur as a library; Cornichon's slim vendor is the same door with fewer extras), and — beyond CI's reach — the **marketplace-installed plugin**. Both wheel burns (mise-dopufo's five unshipped root modules, mise-ditoja's missing `config/attachment_filters.json`) happened under a fully green suite, because every test entered through the repo's own sys.path and so stood where no consumer ever stands. The exposure compounds by an asymmetry worth naming: **the least-attended consumer rides the least-contractual surface** — MCP breakage is seen by a human-attended Claude within minutes; wheel breakage fails at 00:30 in a journal behind a deadman email. So guards for the quiet door must be **artefact-level** (build the wheel, install it into a clean env, enter through it), never static analysis of the packaging config. Both CI-reachable doors are now walked as artefacts on every push (mise-wahane, closed 2026-08-12): `tests/test_consumer_doors.py` builds the wheel, installs it core-only into a clean venv, imports it from a neutral cwd, and drives `server.py` over real stdio — with three known-bad controls that each narrow-reddened naming their door. mise-dehebi (ambient ADC, shipped 1.53.0, waiting on Garni's live run for its done-condition) and the `mise_en_space` facade (mise-dareti + mise-jabeka worked example, shipped 1.54.0) have now turned the wheel door from an accident glaneur tolerates into a *contract* — a credential provider plus a documented library API — which raises the stakes on keeping it walked. `tests/test_consumer_doors.py` imports the facade through the built wheel in a clean venv and drives credential-free `do()` probes through it.

**The door is one scoping axis; ambient machine state is the other, and its divergence is always in the flattering direction (2026-08-12).** mise's unit suite consulted the developer's personal OAuth token through an innocent-looking seam — `web_link` resolves the user's identity to decide whether a thread is self-sent — so a test asserting "no warnings" was green on every machine an author would ever use and red on every runner CI would ever use: sixteen runs, three publishes, two days, zero signals anywhere a human sat. The class fix costs one autouse fixture: `tests/unit/conftest.py` pins `MISE_TOKEN_PATH` to an absent file so every dev run stands exactly where CI stands; the three credential-machinery test modules (`test_token_store`, `test_http_client`, `test_search`'s source defaults) state their env explicitly with module fixtures — they are the only tests entitled to an opinion about it. The control that proves the fix is running the OLD failing case unpinned and watching CI's red reproduce locally. Never delete the conftest pin to make a test pass. Why it survived two days is a separate, unclosed gap: no surface names a red CI at the moment of action — prose rules ("read the CI result") don't fire at push time; that routing question is carte-kucozu on the ~/.claude board.

## Which code does your probe actually reach?

**Two divergences live in this repo, they point in opposite directions, and both are silent. Before believing a red or a green from any probe, name the file on disk it imported — `__file__` is one print.**

**Upward, toward published code.** The plugin's `mcpServers` block spawns the server with `--project ${CLAUDE_PLUGIN_ROOT}`, i.e. `~/.claude/plugins/cache/batterie/mise/<version>/`. So `mcp__*` calls always exercise the **published plugin**, never the working tree, and **no session restart changes that** — which makes "smoke through the MCP envelope, then publish" circular by construction: the only envelope available runs the code you were trying to test before shipping it. The break is `scripts/smoke_stdio.py` — same FastMCP stack, same `@mcp.tool` wrapper, same JSON on the wire, just not spawned by Claude Code. It is not a substitute for re-verifying against the installed artefact afterwards; the assembler and the flavour transform sit in between. Corollary, filed as `bds-sawalu` on the **batterie** board: a long-running session stays pinned to whatever plugin version it loaded at start, so an old session runs superseded code while its Claude reasons from a current working tree, with no tell. The topology behind it: stdio plugin servers are **one per Claude session**, version fixed at spawn from the then-installed cache dir, dying with their session — four Claudes means four servers, and two sharing a version are still separate processes. `ps -eo args | grep cache/batterie/mise` settles who runs what — but never through `sort -u`, which collapses the census to one-per-version and briefly convinced a session the architecture was shared (2026-08-08).

**Downward, toward stale code.** `[tool.hatch.build.targets.wheel.force-include]` in `pyproject.toml` lists nine root-tier modules (`models.py`, `validation.py`, `retry.py`, `filters.py`, `html_convert.py`, `markdown_import.py`, `cues_util.py`, `logging_config.py`, `auth.py`) so the wheel is complete for library consumers like glaneur. **force-include has no notion of a source mapping, so it copies those files physically even into the *editable* wheel** — while the layer directories (`adapters/`, `extractors/`, `tools/`, `workspace/`) ride the `.pth` and always resolve live. site-packages precedes the `.pth` path in `sys.path`, so **the copies win** for any process whose `sys.path[0]` isn't the repo root. Measured three ways: a script under `scripts/` → the copy; a script at the repo root → the working tree; a script in `/tmp` → the copy.

**And `uv sync` does not refresh them, which is what makes it durable rather than transient.** Plain `uv sync --all-extras` considers the editable install satisfied and rebuilds nothing; a shadowed `validation.py` was once found 222 lines behind, missing two functions that had shipped. Only an explicit `uv sync --reinstall-package mise-en-space` rebuilds. Two things follow. **`smoke_stdio.py` is honest only by accident** — it imports nothing from mise itself, and the `server.py` it spawns sits at the repo root, which is the one location that resolves live. One `from validation import diagnose_fetch_404` in a probe under `scripts/` silently tests an older parser. And **after a reinstall the state is maximally deceptive**: the copies are byte-identical, so any diff-based check passes while the mechanism stays fully intact — a green with a shelf life, same family as the plugin-cache row in `traps.md`.

**Now mechanically enforced.** `TestProbeScriptsSeeTheWorkingTree` in `tests/unit/test_architecture.py` requires any script under `scripts/` that imports a root-tier module to put the repo root on `sys.path` **first**, failing with the remedy inline; root modules are discovered by glob. **The guard has no live example** — `capture_fixtures.py`, the one file that exercised it, was deleted the same day (mise-sowepo) — so its two narrow-red controls are its only evidence, which is exactly why they were run: a purely preventive guard with no live example is otherwise indistinguishable from a vacuous one. Two deliberate gaps: a probe in `/tmp` is unreachable by any repo-side rule, and **version** drift is left alone as a trigger because the installed dist-info lags `plugin.json` after every publish. Version drift is the leading indicator; the import path is the harm.

**The companion: a probe's *display* is part of the probe.** `smoke_stdio.py`'s first draft truncated output at 400 characters and printed only the `error` field — so the teaching text its cases exist to check sat past the cut, and the one case that genuinely *succeeded* rendered as a blank line, because success has no `error` field. It reported `3/3 passed` while the screen showed what looked like three failures. This is the truncation trap in reverse: a truncated view read as a **null**, and a null read as a **failure**, is as available as the usual direction and feels even more like diligence. **When a probe surprises you, check the instrument's rendering before you doubt the subject.** Cheapest instance of the family (2026-08-12): `head -c` on a command that prints a WARNING before its ERROR shows only the warning — a truncated view of a two-part message reads as success, so assert on the VALUE you needed (a token length, that day), never on the absence of visible complaint.

**The same family, one layer lower: never substring-grep raw MIME (2026-08-09).** A check for the Drive-chip markup in a real draft grepped the base64-decoded RFC 822 blob for `gmail_drive_chip`, got False, and the markup had been there all along — quoted-printable splits any string across soft line breaks (`gmail_dri=\r\nve_chip`). Parse with `email.message_from_bytes` and `get_content()` per part, *then* grep. Generalises past MIME to any transport encoding sitting between you and the bytes you mean to match: **a substring probe is only valid on the decoded representation**, and it was caught here only because the repo's own check-the-instrument line fired first.

**And that lesson immediately produced its own counter-example in CLAUDE.md.** A session wrote that `uv run --all-extras python -m pytest` here "prints no `N passed` summary line" and sent readers to `pytest --co` for a count. **It does print one** — `2110 passed, 100 deselected` as the last line of 92 — and the claim was false when written. The mechanism is legible: `-q` suppresses the *per-test* lines, the coverage table is ~85 lines long, so the count sits at the bottom of a long scroll, and a session freshly burned by `-v` cancelling against `-q` read a screen with no `PASSED` lines as a screen with no summary. It then corrected the `-v` clause in the very next paragraph and **left the wrong headline standing** — `verification.md`'s "a partially corrected artefact is more dangerous than an uncorrected one", inside one file within one hour. **A correction covers what it names and nothing adjacent: re-run the thing the claim is about, not the thing your correction is about.**

## A capability can be absent for six months because nothing ever probed it (mise-mahiho, 2026-08-10)

**mise could not read the staff directory, and the reason was never ITV's permissions — it was our own scope list.** Every directory 403 said `ACCESS_TOKEN_SCOPE_INSUFFICIENT`. One consent click settled it: both candidate routes returned 200 with no administrator rights, no IT ticket and no Workspace config change. Search the repo's whole history and there is not one commit, bon item or handoff line that ever attempted it. **This is `verification.md`'s "an unverified reason to act gets tested by reality; an unverified reason NOT to act never does" with a six-month price tag** — the belief cost a capability every week and produced no failure to notice, because not-acting generates no result to be wrong about.

Three things kept it invisible, and the first generalises hardest. **An unused scope is not dead weight, it is a false claim about capability.** `contacts.readonly` sat in `SCOPES` from 2026-01-23, was never referenced by a line of code, and was advertised in the README as "Contacts (read)" — so the ground looked covered. It is the user's own address book, nothing to do with the directory. Second, `PERMISSION_DENIED` reads as an org statement while meaning a token statement; the discriminating reason sits one level down in `details`. Third, the working route is named for the wrong audience — "Admin SDK", `admin.directory.user.readonly` — and the only doc that contradicts that is a subsection called "Retrieve a user as a non-administrator". **When a capability is believed absent, check whether anything ever tested the belief before designing around it.**

**Two live facts about scope arithmetic, both counter-intuitive.** Removing a scope from `SCOPES` stops mise *asking* but does **not revoke** — `include_granted_scopes=true` unions the request with everything ever granted to the client, so the live token still carried `contacts.readonly` plus five Apps Script scopes after the "removal". And **`token.json`'s own `scopes` field records the REQUEST, not the grant** — it said 11 while Google's tokeninfo said 20. An instrument reporting its input as its output; ask `oauth2.googleapis.com/tokeninfo` when the answer matters.

**The non-admin property is a construction, so it is guarded as one.** `adapters/people.py` is non-admin only because `viewType=domain_public` rides every request; drop it and the identical call becomes an administrator call. Two tests pin it — every call site sends it, and `admin_view` never appears in executable code (ast-based, so prose stays free). The measurement that makes this evidence rather than hope: the same call *without* `domain_public` returns 403 "Not Authorized", **a different error** from the scope-insufficient 403s. **When a security property depends on a parameter rather than on identity, test for the parameter, not the outcome** — the outcome looks identical right up until it doesn't.

**And a bug class the unit tests were structurally blind to.** `do_search` set a local `search_people = "people" in sources`, shadowing the imported adapter function of the same name; every real call raised `'bool' object is not callable`. All the adapter tests passed because they call the adapter directly and never cross that scope. Live smoke caught it in one run. **When a module imports a function and the caller derives a boolean about the same concept, the names collide by default** — and the test that catches it must enter through the caller, which is why the regression guards sit at `do_search` level.

*(The `manager` field's board-level artefact, the multi-word `orgTitle='…'` silent zero, and the query grammar all live in CLAUDE.md — they are live contract, not method.)*

## Notes goes stale about mise, and only the NEGATIONS rot (2026-08-10)

**When mise ships a capability, `~/notes` keeps telling Claudes it doesn't have it.** A sweep of the orientation layer (`work/`, `practices/`) found **eight** stale claims across five files — `raw_query` couldn't OR (shipped 27 Jul), Gmail search-scoped URLs were unresolvable (shipped), `file_path` unsupported (shipped), `do(trash)` absent (shipped 19 Jul), Forms "create-only" (shipped 19 Jul). None of them *failed*. The OR claim just bought an extra search every time it was obeyed. **Rot that fails gets fixed within the hour; rot that merely taxes you is immortal** — which is why nobody had noticed in two to three weeks.

**Every stale claim was a negative, and that is structural rather than lucky.** Capabilities get added and essentially never removed, so *"mise can do X"* stays true indefinitely while *"mise can't do X"* is a decaying asset whose half-life is the roadmap. So the check is a grep for negations near the word, not a review — seconds, not an afternoon. Tool: `~/notes/practices/mise/check-mise-claims.py` (`--self-test` first, `--all` to include dated captures). **Run it after any release that changes what mise cannot do.**

Two disciplines the sweep itself proved. **A dated capture is allowed to be stale; an orientation file is not** — handoffs and hunt docs were true when written and rewriting them destroys evidence, so a correction that matters goes into the room's *durable* file with a pointer back. And **the checker's own first run scored 1-in-5 precision on its HIGH pile** — two hits were the sweep's own corrections (the dateline sat two lines above the quoted stale sentence) and two were `mise` appearing inside a deposit *path*. Reading the five hits, rather than trusting the count, is what caught it; the fix was a subject-vs-path discriminator plus a windowed correction check, and the synthetic false-positive case is now pinned in `--self-test`. Same lesson as the `has_data_table` 31/40: **a classifier total is a hypothesis until you have read what it caught.**

**And the sweep committed the sampling error this file already names, live, while writing the lesson down.** The checker was scoped to `~/notes` — the surface where the rot was found — while **mise's own `instructions.md`** carried exactly the same species: its Drive-API row used folder creation as the worked example of *bypassing* mise, months after `do(create, doc_type='folder')` shipped. That file loads into every session of every mise user — the highest-traffic guidance surface in the estate — and the cost was paid the same day by a different session, which hand-rolled a Drive-API script it didn't need (mise-kagejo). "A sample taken where you already suspect a problem confirms the problem and hides its extent" was written above about module sizes; it recurred verbatim about guidance surfaces. **When you name a rot species, immediately ask which OTHER surfaces have its shape** — and that extension shipped the same day the lesson was written: `tests/unit/test_guidance_freshness.py` (mise-gaseve, closed 2026-08-10) sweeps the three vendored guidance surfaces from inside CI. The notes-side sibling cross-points at it; two checkers, two surfaces, deliberately unmerged.

**The method under that test generalises: when a rot species can't be verified mechanically, gate its DELTA instead of its truth.** No regex can tell a stale "mise can't create folders" from a true "the Docs API can't create suggestions" — truth lives outside the text. But you don't need truth to stop the rot: sweep for the species' *shape* (here, an undated negation naming a shipped op or sharp param), read and enrol every current instance once in an ADJUDICATED allowlist with a reason string, then fail anything NEW that wasn't deliberately judged — and fail any enrolment whose line has vanished, so the allowlist can't rot in the opposite direction. The gate converts an unverifiable property ("all guidance is true") into a verifiable one ("every claim of this risky shape was consciously judged, once, with the reason recorded"). Same move as the module-size ratchet — freeze the present, police the delta — applied to prose, and it composes with the estate's dating convention: a dated line is already adjudicated, so the sweep skips it for free. Two live edges: the allowlist keys on line PREFIXES, so rewording an enrolled line reds `test_adjudicated_entries_still_match` by design — the failure message teaches the remedy; expect it mid-edit rather than reading it as flaky. And implicit negation-by-example (the original kagejo rot — "when bypassing mise (e.g. folder creation)" carries no negation token) remains uncatchable; the checker guards explicit claims only.

## The generic primitive beats the convenience alias

When mise added `archive`, `star` and `label`, `label` was already the superset — archive is `label("INBOX", remove=True)`, star is `label("STARRED")`. A brief proposed adding `mark_read`, `mark_unread` and `unstar`. The right move was **zero** new operations and better docs, because each new op name costs in three places: the tool description (hard-capped at 2048ch), the dispatch table, and Claude's reasoning about which verb to pick. **Before adding a do() operation, check whether an existing one already handles it with different parameters.** The description ceiling makes this a resource constraint, not an aesthetic.

Three worked examples. **wemuki** landed three missing capabilities — form edit, draft update, trash/discard — as ONE new op with **zero new schema params**, so the signature seam stayed green by construction. **buzafo** closed the whole gather-into-a-folder workflow with *no* new operation, by giving one existing verb one honest flag: `fetch(attachment=…, raw=True)` deposits the attachment's original bytes beside the extraction, so a Gmail-only PDF stops being unreachable. **`do(copy)`** became the 18th op only because nothing stretched to duplication — batch-first, pre-flighting `canCopy` so **`blocked` is reported separately from `failed`**, and refusing folder sources because `files.copy` doesn't recurse and you would get an empty folder that looks like success. Its `blocked` path is unit-tested but **never live-fired**: nothing in this Drive has `canCopy: false`.

Recorded because the sequencing was got wrong out loud — stripping `doc_type='slides'` was announced as a *prerequisite* for copy on the grounds it would free description budget, and it freed **seven characters**. **Measure before asserting a dependency someone is going to plan around.**

When you *do* add one, the op name and count drift more surfaces than CLAUDE.md's recipe lists: `test_dispatch.py` auto-verifies OPERATIONS/DISPATCH sync, but the "N ops: a, b, c…" line lives un-policed in CLAUDE.md, README.md, `DO_DESCRIPTION_FULL`, `docs_do()` and the SKILL.md table.

## The data you need may already be in hand

Before adding an API call — or assuming a scope change — check what the existing fetch already downloads and discards. samono added `last_sender`/`from_me`/`unread_count` plus a snippet to Gmail search for **zero** extra calls: the per-thread fields mask already pulled every message's headers and labelIds, and the old code only read `messages[0]`. Same evening, meduto's invite-state enrichment needed no scope change because `calendar.readonly` already covers `events.list`.

**The write side has the same shape** — three instances in one week: Gmail sendAs signatures read under the already-held `gmail.modify`; the Sheets WRITE scope had been in SCOPES *and the granted token* all along; and `adapters/sheets.py` already carried `update_sheet_values`. Before pricing a feature as "needs a new scope / re-consent / new adapter", run the one-probe checks: **read the granted token's `scopes` array** (not just `oauth_config.py`), grep the adapter for existing helpers, hit the endpoint read-only with the live token.

## The MCP description length ceiling

MCP tool descriptions have a hard ceiling at **2048 characters**. Over it, the description is truncated *and* — the insidious part — the Anthropic API silently drops properties from the tool's JSON schema during `tool_reference` expansion. The loss happens API-side, so CC's permissive schema never gets a chance to help, and the dropped property appears nowhere: not truncated, just absent. `do()` currently declares 26 properties, so going over would silently lose some.

**Fix within our control:** keep descriptions short and put detail in MCP resources (`mise://docs/*`). This is **now mechanically enforced** by `tests/unit/test_tool_description_budget.py`, which carries three asserts: the hard ceiling, a **headroom floor that fails at <100 characters remaining** (so it fires while there is still room to think rather than at the cliff edge), and a check that every op in `DISPATCH` is actually advertised — an undocumented op is unreachable in practice. This section documented the ceiling for months and nothing checked it; adding `do(copy)` took the description to 2036 of 2048, and only a hand measurement caught it. Expect the next person adding an op to meet the headroom assert — that is the design, not a defect. Applies to all batterie MCP servers, not just mise.

## Remote mode architecture

Remote mode was designed around *not touching the fetchers*. The 10+ type-specific fetch functions in `tools/fetch/` are battle-tested and complex, so rather than making them remote-aware, the orchestrators **intercept after the fetch completes**: deposits go to a temp dir, content is read back and included inline, temp dir cleaned up. This post-hoc read-back means all fetchers work unchanged in both modes. Same for search — `SearchResult.to_dict()` already had an inline mode. **Keep the interception in `tools/remote.py`, never inside the fetchers.**

Operation gating is a **whitelist** (`REMOTE_ALLOWED_OPS`), not a blacklist; error messages list only allowed ops, never restricted ones. The tool description adapts per mode via a conditional `description=` on `@mcp.tool()`, which requires `_REMOTE_MODE` to be set **at module load time before decorators run** — for containers use `MISE_REMOTE=1`, because `sys.argv` detection is fragile under process managers.

## Remote deployment path — superseded, don't build it

Explicitly **single-user** (one `token.json`, one `lru_cache(maxsize=1)` per service); multi-tenancy would need per-request credential injection, which is architecturally significant. The hosted path — auth middleware → token management → containerisation (mise-tokiju / winala / sefepo) — is now **superseded rather than merely parked**: mise-mawawa reaches claude.ai and mobile by pointing an ITV-owned OAuth client at Google's managed MCP servers, which is the same goal achieved as configuration with zero infrastructure. Re-open only if that route fails.

Live invariant if a long-running server ever exists again: token refresh needs the token file refreshed AND `clear_service_cache()` called AND services rebuilt — the `lru_cache` bakes a `Credentials` object in at service creation time.

## OAuth and credential architecture

The OAuth client is installed-app type, so the client secret is intentionally distributable and `credentials.json` ships with the repo; **the real secret is the refresh token.** Two GCP projects, two clients: mise's production client lives in ITV's `mit-workspace-mcp-server`, and a second in `planetmodha-tools` backs daemon use under `claude@planetmodha.com`.

**OAuth client User type matters and is invisible from `gcloud`.** The `mit-workspace-mcp-server` consent screen is **Internal**, so any `@itv.com` Workspace user authenticates without verification or a test-user list — bypassing Google's ~6-week verification for sensitive scopes. External-test caps at 100 explicitly-added users; External-published shows a "Google hasn't verified this app" warning. The setting lives only in the console, not the CLI. **For any future ITV-internal MCP, default to Internal.**

**Token storage:** macOS Keychain (`mise-oauth-token`) is the source of truth; `~/.claude/plugins/data/<name>/token.json` is the persistent fallback, and on Linux that file *is* the source of truth (the "Keychain storage failed" line there is benign). The plugin-staging-dir path is ephemeral on Cowork and must never be relied on. The canonical bootstrap is `do(setup_oauth)`, which the friendly error in `adapters/http_client.py` names verbatim when the token is missing — Claude reads the error and calls the remedy.

**Re-auth: revocations are account-level, not a mise bug.** A security event on `sameer.modha@itv.com` (password change, 2SV change, admin sign-out-all) revokes *every* OAuth grant for the account regardless of client — don't hunt for a code cause. **Rejected remedy, recorded so it isn't re-proposed: a dedicated per-mise OAuth client in its own project.** Account-level revocation kills all grants regardless of client, so it would not have protected anything; don't re-propose without a *client-specific* failure. On headless/xrdp tube use the account-agnostic `--code` flow — `uv run python -m auth` (print mode), click the URL in a browser signed into **itv** (the Mac), paste the redirect back. Tube's own xrdp browser is signed into planetmodha and this client is Internal to itv.com, so any browser/listener flow barfs there. Two diagnostic traps: **the call log records `ok:None` for successes** (a populated `result` means it worked), and `localhost:3000` is shared by other tools' OAuth spikes, so check the `client_id` before attributing a `:3000` callback to mise.

**Three fragilities have code answers (zikesa).** Concurrent flows no longer clobber — `.pkce_state.json` keys verifiers by the OAuth `state` param, and a redeem with no findable verifier raises BEFORE calling Google, preserving the single-use code. Stale-server tokens self-heal — `_refresh_or_reload` re-reads the token file when Google refuses the in-memory grant, so **"restart the MCP server after re-auth" is no longer required**. And `can_open_browser()` returns False under `XRDP_SESSION` or `MISE_NO_BROWSER=1` — best-effort only, which is why the explicit override exists: detection cannot know account *suitability*.

## Guest mode — caller-owned credentials (mise-lebapo, 0.7.8; mise-kivane, 0.7.9)

Set `MISE_TOKEN_PATH` and mise runs as a guest: it loads the caller-owned token at that path, never writes back, and persists nothing of its own — no Keychain, no plugin-dir fallback. This is the path for an embedding host that owns its own credential lifecycle.

Three sharp edges shaped it. **Guest tokens are often ADC-shaped**, not mise's own `token.json`, so they're loaded directly rather than assumed into mise's schema. **When the credentials carry a quota project, mise sends `x-goog-user-project`** so billing attributes to the caller's project. And **a guest token may carry no Gmail scope**, so guest mode defaults an omitted `search` source list to `['drive']` — a Gmail search on a Drive-only token would otherwise fail confusingly.

## The library door: constructor identity rides the existing accessors (mise-dareti, 1.54.0)

`mise_en_space` is the blessed library facade — one class, `Mise(credentials=|token_path=|ambient=True, base_path=)`, with `.search/.fetch/.do` — the wheel-consumer contract for glaneur and Garni. The durable design lesson: **when adding a new way to SELECT an existing mode, put the state behind the mode's existing accessor functions rather than adding a parallel check at each consumer.** Constructor identity went into `token_store.configure_identity()` as in-process state that `override_path()` and `ambient_mode()` consult — and every downstream gate (guest-mode teaching errors, ambient search narrowing, mailbox-op refusals, `resolve_token_path`'s guest handling) fired correctly for constructor-selected modes with **zero consumer changes**, because they were already asking the accessor rather than the env var. The alternative — a third check beside each existing `override_path() is not None` — would have been a scatter of near-misses. Code-plus-env identity collisions refuse rather than pick a winner; identity is never selected by mutating the environment. The worked example (`examples/hydrate_and_write_back.py` — examples/ vendors, verified in assemble.sh's exclude list) ran live end-to-end as the agent-spike service account, including `do('trash')` through the facade. Still open: `Mise(ambient=True)` has run against an impersonation ADC file, which exercises `google.auth.default()` end-to-end, but never a REAL metadata server — Garni's Cloud Run run (agsp-cudoba) is the first true proof, and it is what mise-dehebi's done-condition waits on.

## Google Sheets: the merged-cell trap

Google's Sheets value APIs return *display* data, not *structural* data: merge ranges live in the metadata endpoint (`spreadsheets.get`), not the value endpoint. Fetch values with `FORMATTED_VALUE` and a merged cell returns its value only in the top-left cell; every other cell in the range comes back empty. The fix requests `sheets.merges` in the metadata fields and `_resolve_merges` propagates top-left values post-fetch, horizontal merges included, with a warning cue.

**Sheets editing (lirugi) added no new ops** — the generic-primitive principle — **and the anticipated range extension shipped exactly as this file predicted (mise-vadoko, 2026-08-08)**: A1 notation on a new `range=` param, no new operation, and `update_sheet_values` in `adapters/sheets.py` already did the whole write (the check cost one read; the "expensive" feature was wiring). Three grains: bare tab name = tab-scoped clear-and-replace, bounded range = exact cells with nothing cleared, anchor = CSV's shape spills from there; USER_ENTERED throughout.

**Links and chips followed the same evening (mise-bazuvo), and the gating probe killed the brief's fear: `chipRuns.richLinkProperties` IS writable via plain REST batchUpdate** — no Workspace-tier gate, probed on the ITV tenant 2026-08-08. Two facts shape the design. First, **a smart chip replaces the cell's value with the target's live title** (Google enriches server-side — write `@` + chipRuns, read back the filename), which is the feature for an artefact index and corruption for a URL-consuming column — so chips are explicit opt-in (`@url` as the whole cell) and a bare URL stays a URL. Second, **the writer is two-pass to keep type inference**: the plain grid rides `values.update` USER_ENTERED (numbers/dates/formulas parse as ever), then one `batchUpdate` overlays `textFormatRuns` (fields mask touches ONLY the runs — the value stands) and chips onto just the decorated cells. `[label](url)` supports several links in one cell — the case `=HYPERLINK` structurally can't do and the 2026-07-27 lawyer-sheet incident needed. Two adjacent facts, the first now settled: **Docs-side chips SHIPPED (mise-rafote, suite 1.46.0)** — the current Docs API Request union carries `insertRichLink` (plus `insertPerson`/`insertDate`, all newer than training memory, which is why the check-the-current-reference-first instinct keeps earning its place). Same accept-and-enrich family as Sheets: `richLinkProperties` takes the `uri` ONLY — a supplied title is a 400 ("should not specify a title") and Google enriches title/mimeType server-side; non-Workspace URLs are a 400 ("The URL is invalid"). mise's syntax is whole-line `@url` in `do(create)`/`do(overwrite)` (`tools/doc_chips.py` — a fresh sibling because create.py is ratchet-frozen), atomic batchUpdate with placeholder-restore on failure. A mise-written chip fetches back as a markdown link carrying the target's LIVE title (measured through the 1.46.2 envelope, 2026-08-09) — chipness doesn't survive a fetch→create round-trip, but title and URL do, and the enriched title doubles as read-back proof the chip landed. And a one-letter API asymmetry that produced a false double-zero probe, now known to run INSIDE Docs as well as across products: **Sheets spells the link key `link.uri`, Docs spells it `link.url` — and Docs chips spell it `richLinkProperties.uri`** — a walker keyed on the wrong one reports links as absent while staring at them. Read any fresh-probe double-zero (no chips AND no links) as instrument first, subject second: two simultaneous genuine negatives are rarer than one wrong field name. **Slides is the recorded chip negative (mise-gosadu, 2026-08-09), and it is total:** zero chip/richLink/person surfaces in the current Request union (45 request types) AND zero in the presentations resource — the API can neither write a chip nor even represent one on read — and a live `insertRichLink` against a real deck 400s with "Unknown name … Cannot find field", so the reference isn't stale. Chips in Slides are UI-only; don't re-propose an API route without evidence the schema changed. **Gmail's chip is compose-time markup, not a platform object (mise-musepe, 2026-08-09):** the native composer's Drive chip is plain styled HTML on the wire — `class="gmail_chip gmail_drive_chip"`, inline styles, a public icon URL keyed by MIME type (`drive-thirdparty.googleusercontent.com/32/type/<mime>`), nothing proprietary — and Gmail does NO read-time upgrading (an A/B probe of shared vs unshared plain links rendered identically). The instrument generalises: **when a Google surface renders something richer than mise emits, diff what the native composer puts ON THE WIRE before assuming a platform object** — send the native artefact and mise's version to the planetmodha mailbox, pull both raw HTMLs via the mise-home token, diff. The two-tenant setup is a built-in A/B lab for any recipient-side rendering question. So mise's `include=` now emits that exact markup (`_format_links_html` in tools/draft.py, style values Google's verbatim) and recipients get real chips; delivery preserves it byte-intact, verified on a received message. The recorded negative boundary: the composer's recipient-access check ("Share & send") is the one part mise can't take — resolving recipient ACLs through groups/domain shares correctly is server-side work, and a wrong "not shared" warning is worse than none. The skill teaches share-first instead. **The contract change to know: un-ranged overwrite on a MULTI-tab sheet now refuses and teaches `range=`** — the old behaviour (clear first tab, warn about the rest) was the 15-people-on-a-shared-sheet footgun the item existed to kill. Single-tab sheets keep the old wholesale contract. `replace_text` is substring + matchCase + formulas-excluded across all tabs, with an `occurrences_changed` cue. `prepend`/`append` reject, naming the two alternatives.

## Google Calendar: two traps (2026-07-07)

**The list API hides cancelled events rather than marking them.** `events.list(iCalUID=…)` returns 0 items for a cancelled event unless `showDeleted=true` — absence-of-result is indistinguishable from never-existed. **Any event-state code MUST pass `showDeleted=true`.** Mechanism and probe evidence: `docs/2026-07-07-meduto-invite-event-state.md`.

**Invite-state disclosure is shipped (pinodi), and the cost split is the design.** An invitation email is a frozen snapshot — its ICS says CONFIRMED forever — so mise overlays the LIVE state. **search** carries a free `has_invite` boolean at zero extra calls; the fields mask had to go one level deeper than obvious, because invites nest `text/calendar` inside `multipart/alternative`. **fetch** resolves the UID to `cues.invite_state` plus a STALE SNAPSHOT warning when cancelled, at most two extra calls and only when a thread carries an invite. Two invariants for anyone editing this: the ICS is trivial-filtered out of the user-facing `attachments` list (correct), so `_build_message` keeps it separately on `EmailMessage.calendar_attachments` for the UID lookup; and a guest token may lack calendar scope, so `_enrich_invite_state` swallows any error and returns None — **enrichment never fails the fetch.**

**The cap ate the future, and the fix has three legs that only work together.** Google returns events oldest-first, so a single capped page fills with last week before ever reaching tomorrow. The fix: pass the query to shrink the result set, paginate the full window internally, and use nearest-now selection to decide who survives a genuine overflow (`calendar_truncated` cue). **Any one leg alone re-breaks "is tomorrow's meeting still on?"** Note the downstream cost, now filed as mise-riduka: making the query ride the API `q` param is exactly what makes a query *mandatory*, so clash-checking a diary with no topic term is currently impossible.

**Calendar writes: the scope arrived for RSVP and nothing else (2026-08-09, one day's arc — zikele → forunu → gepiwe).** The morning decision was read-only: `attachments[]` IS writable via events.patch + `supportsAttachments=true` (current reference, worked example), but the write cost scope + re-consent against zero demand. The same day produced the demand: Sameer asked for accept/decline from triage, mise-forunu measured the zero-scope route dead (the invite email's `action=RESPOND&rst=N&tok=…` links 302 to an accounts.google.com sign-in and responseStatus stays needsAction — the tok pre-authenticates identity, not the write; don't re-probe it), and Sameer chose the scope over a CDP-browser workaround. So `calendar.readonly` was SWAPPED for `calendar.events` (same scope count — the adapter is events-on-primary only, so every read is covered) and **`do(respond)` shipped as the 19th op**: `file_id` = invite thread id (resolved via the same iCalUID machinery as invite_state, disclosed in cues) or event id; the write is read-modify-patch of the FULL attendees array, because **Calendar patch semantics replace array fields WHOLESALE** (probed live before building — a self-entry-only patch would silently drop every other attendee from the copy). Google-native invites' iCalUID is `<eventId>@google.com`. Refuses cancelled meetings and no-self-attendee events; excluded from REMOTE_ALLOWED_OPS (organiser-visible mutation); a stale-scope token gets a teaching 403 naming setup_oauth force=True. Re-consent is lazy per flavour — ITV done 2026-08-09, mise-home whenever its calendar matters; older tokens keep working for everything except respond. **Event-attachment write remains unbuilt** — demand is still zero — but the scope barrier is now sunk, so if demand ever arrives it is wiring, not consent.

**Record a negative WITH its surviving routes, and the negative becomes a decision menu.** forunu's close note named three routes past the dead RSVP links (scope + re-consent / logged-in CDP browser / stays manual); Sameer read it and picked the scope within the hour, and respond shipped the same morning. A bare "doesn't work" would have parked the question. Same shape as zikele: "reopen on a real demand instance" met its demand eight hours later, and because the cost analysis was already recorded, nothing needed re-deriving.

## Google Docs: checkbox tick-state is export-only (mise-pirozu, 1.6.0)

Google Docs checkbox **checked-state is not in the Docs API — it is export-only.** `documents.get` returns a byte-identical bullet dict for checked and unchecked rows; a full-JSON deep scan finds no checked field. The `~~` on checked rows in the `text/markdown` export is **synthesised by Google's renderer from the checked bit — it is NOT `textStyle.strikethrough`**, which is FALSE on checked rows, so it cannot be read from the API. The only way to read ticks is a rendered export. (The banked brief guessed "tick == strikethrough" — a wrong mechanism, corrected before building.)

mise's approach: detect a checkbox list, fetch the `text/markdown` export as an oracle, parse markers in document order, and tag each paragraph in place so the pure extractor renders `- [x]`/`- [ ]`. **One extra API call, gated on `is_checkbox_list`, so zero cost otherwise** — the same checkbox-oracle pattern wofomu later reused. Positional alignment is exact on single-tab docs, and a count-mismatch guard renders plain bullets plus a warning — **never a wrong tick**. **Multi-tab tick rendering is untested**: the guard falls back safely on desync, but real multi-tab alignment is unproven.

## Doc comments: read side, write side, and a create/list field trap (mise-cudire, 1.7.0)

mise reads comments (deposited as `comments.md`) and writes them: `do(comment)` opens a NEW unanchored thread, `[agent]`-prefixed; `do(comment_reply)` replies to an existing thread by `comment_id` and can resolve it.

**Drive's comments API has a create/list field asymmetry: `mentionedEmailAddresses` is valid for comments.LIST but 400s on comments.CREATE.** Crucially **the comment is STILL created** — Google persists the resource, then fails serialising the response fields — so a create that 400s can look like a failure while actually succeeding. `_SINGLE_COMMENT_FIELDS` in `adapters/drive.py` deliberately omits it; **don't "tidy" it back to match `COMMENT_FIELDS`.** General lesson: mocked tests can't see field-selection validation, so a do()-op hitting a real Google write endpoint needs a live smoke before you trust it — 16 mocked tests were green and the first real create 400'd.

**Read-side location.** `comments.md` used to be flat and in API order, so a comment anchored on a **heading** — a decision about a whole section — read identically to a comment on one line. `extractors/comments.py` now correlates each anchor against the parsed document, **reorders comments to document order** (unmatched last, with a warning) and renders a `↳` locator, flagging container-anchored ones with `⚠`. Live invariant: **sheets and slides deliberately pass no content and keep the flat API-order render** — location is doc-only, and an inline snapshot enforces it.

**Anchored comment *write* is a platform dead-end, and then turned out to be the wrong goal anyway — don't re-propose either half.** A real comment's `anchor` is an opaque `kix.*` ID minted by the Docs *editor*, and `comments.create` **stores whatever string you send verbatim and never resolves it**, so a 200 plus an id proves nothing; five attempts across four formats all read back `quotedFileContent=''`. Then the reframe dissolved the need: the triage loop wants **replies to the human's threads**, and a reply attaches by `comment_id` to a comment that already carries the human's editor-minted anchor — **so the reply inherits the anchor for free**. The round-trip is already complete and shipped.

## Google Docs: suggested edits (mise-wofomu, suite 1.19.0)

`fetch(suggestions=)` closes the silent-loss gap on Docs carrying suggested edits. API mechanics, bought with live probes: `documents.get` defaults to an inline mash for editors — every suggestion-tagged textRun carries `suggestedInsertionIds`/`suggestedDeletionIds`, and **the insert and delete halves of a *replace* SHARE one suggestion id**, which is how markup mode pairs them. `PREVIEW_SUGGESTIONS_ACCEPTED` returns the suggester's intended text server-side; `PREVIEW_WITHOUT_SUGGESTIONS` the original. **The API never exposes *who* made a suggestion.**

Modes: `accepted` (default), `original`, `markup` (`{++ins++}[s1]`/`{--del--}[s1]`, shared `[sN]` = one replace). First call is always SUGGESTIONS_INLINE (countable); preview modes cost a second `documents.get` only when suggestions exist — the checkbox-oracle gating pattern again. Two honest edges: **counting is text-level only**, so a doc with only structural suggestions fetches without the warning; and view-only access requesting SUGGESTIONS_INLINE on someone else's doc is **untested** — if a view-only fetch errors on the first call, that is where to look.

## Drive revisions: no names, no pins, but recoverable content (mise-cizuzi, suite 1.20.0)

**The Revision resource on native Docs has no `name` field, and `keepForever` is binary-content-only — both accept the write with HTTP 200 and silently ignore it.** A green response proves nothing; verify by read-back. This falsified cizuzi's briefed design ("named restore points") in three API calls. But per-revision `exportLinks` genuinely work — they 307-redirect to googleusercontent with an embedded token — so historical content **is** recoverable even though versions cannot be pinned or named.

The shipped design pivoted accordingly: every mutating do() op on a Google Doc captures the head revision BEFORE editing and returns `cues.restore_point {revision_id, modified_time}`, the precise Version-history entry to revert to; `overwrite` additionally posts an `[agent]` comment naming it (`restore_comment=False` to suppress). **Capture is best-effort — failure warns, never blocks the edit.**

## Gmail drafts: N objects per thread, ONE rendered (mise-sasivo, suite 1.21.0)

Gmail legally holds **N draft objects per thread while conversation view renders exactly ONE inline** — so a silently created second draft hides exactly where the user hits Send (the Drafts *list* shows a row per object, hence "two red Drafts, one visible"). `reply_draft` therefore lists the thread's drafts first and **REFUSES** when one exists, naming its id and snippet — update it via `draft(file_id=…)` or pass `supersede=True` to discard-then-create. The check is **fail-open with a warning cue** (a listing hiccup never blocks the draft); `supersede` is rejected in remote mode, because drafts.delete is permanent and the discarded draft may carry a human's hand-edited words — **the refusal's snippet exists so the caller checks whose words they are first.**

Adapter trap: **`drafts.list` under a fields mask returns a ZERO-LENGTH body (not `{}`) when there are no drafts** — it will crash a naive `orjson.loads`; `list_thread_drafts` parses raw bytes.

## Drive search: pagination, raw query, and AND semantics (suite 1.24.0–1.25.0, 2026-07-27)

**Drive search silently capped at 100 results for a year, and the root cause is the instructive part: `nextPageToken` was never listed in `SEARCH_RESULT_FIELDS`, so the API never sent it.** The signal wasn't ignored by buggy code — it was never requested, which is why a year of capped searches produced nothing to notice. Gmail had paginated correctly the whole time, so the two sources disagreed silently. `search_files` now pages to `max_results` behind a 10-page / 1,000-result guard.

**Two cues answer different questions and both can fire — don't collapse them.** `drive_truncated` = *fetched vs matched*, and it is **exact**, derived from a surviving page token, so it distinguishes 25-of-25 from 25-of-1292. `preview_partial` = *shown vs fetched*, and fires on every source. Open edge: a 1,000-result deposit is a large JSON (probe runs wrote 2.4 MB).

**`raw_query=` passes Drive's own query language through unescaped** — `or`, `not`, `name contains`, `modifiedTime >`, `'x' in owners`. Drive-only, mutually exclusive with `query`, composes with `type`/`folder_id`, `trashed = false` still ANDed on. Its twin is `looks_like_drive_query()`, which **refuses** operator-shaped input typed into plain `query`, because that used to keyword-search the operator *words* and return confident nonsense. **`raw_query` is unescaped by design** — correct for single-user stdio against your own Drive; if mise ever grows an untrusted caller, this is the first thing to revisit.

**Plain `query` is AND across every word — proved by control, not documentation.** A nonsense token returned 0 against a query that otherwise matched hundreds. This *inverts* the standard advice: when a search returns nothing, the fix is usually to **drop terms**, not to be more specific.

**The URL-decoration rule — resolve, don't validate — shipped as the pointer pattern (mise-dogape, suite 1.42.0).** Five decorations — `?gid`, `?tab`, `#heading`, `#slide`, `?disco` — parse at the `detect_id_type` seam and resolve **post-fetch against the deposit alone**, zero extra API calls, because mise already downloads everything the ids name; the design cost was three small maps recorded in the manifest at write time (doc `structure` with line offsets, tab `sheet_id`s, `slides_index`). Object-id shapes vary wildly inside one product (`p`, `g3f5d00ed841_0_0`, `mig_slide_003`, `t.0`, `t.ems17pqdjs5b`), so **any format regex is wrong on somebody's real document** — strip the one known prefix, treat the remainder as an opaque key, look it up. Three durable sub-lessons. **mise GENERATES content.md, so it can know which line anything lands on — offsets are free at write time and unrecoverable afterwards.** **Non-resolution is staleness DETECTION** (deleted tab, resolved comment), information no API surface offers directly — and Google's own guarantees set the reporting register: immutable ids (tabs) warrant a firm STALE, read-only-but-unguaranteed ones (headings) a gentle one. And **alignment guards beat alignment cleverness when mapping API structure to rendered text**: heading→line mapping works by order+count+level agreement per tab, and on ANY mismatch keeps ids and text but omits line numbers — the checkbox-oracle discipline, never a wrong number. Its watched-red control was a NORMAL paragraph whose literal text was "## fake", the exact input that would have corrupted a cleverer matcher. Known safe gap: headings inside tables render as cells, not `#` lines, so they carry no line number (reasoned + unit-tested, not probed against a pathological real doc). Deposits are byte-identical decorated vs bare — resolution data rides the manifest unconditionally, so narrowing-to-save-context can't recur here. This batch is the repo's strongest case for **probe before building**: four live probes ran before any code and changed the design twice.

## Build flavours: full vs slim (mise-hibere, 0.7.9)

Mise ships in two shapes from one codebase. The **full** build (dev, CI, the marketplace plugin) carries local extraction — `markitdown[pdf]` + `pdf2image` — for fast local PDF text, HTML→markdown and PDF page thumbnails. The **slim** build (what Cornichon vendors) installs plain core: `markitdown` is absent, so `adapters/pdf.py` degrades to Drive server-side conversion, `html_convert.py` to tag-stripping, and PDF thumbnails are skipped. Image fetch still works because `pillow` is core.

**The mechanism is the load-bearing part: the "full" choice rides in the *spawn* command (`uv run --extra extraction`), not the install command.** You can't make an extra on-by-default, so "default install = slim, full opts in" is forced; routing the opt-in through plugin.json means zero estate-wide install-command churn, and the assembler vendors plugin.json so the arg travels. **Watch that arg — if `--extra extraction` is ever dropped, every plugin and Cowork user silently goes slim.**

Two consequences: run the test suite with `--all-extras`, because PDF-extraction tests assume markitdown is present and fail in a slim env; and the slim PDF→Drive fallback needs Drive **write** scope (it uploads to convert), fine for own-Drive PDFs but it would break under a read-only guest token. **Direction of conversion maps to flavour:** HTML→markdown is extraction-extra, markdown→HTML had to go in **core**, because `draft`/`reply_draft` are remote-safe ops that must render GFM in every flavour. Rule of thumb: anything a remote-safe op needs is core; local fast-path extraction is the extra.

What made slim cheap rather than crippling was profiling what the weight actually buys. The 67M monster was onnxruntime, pulled in by magika — markitdown's ML byte-level file-type *sniffer*, which mise never needs because it routes by Drive MIME metadata rather than sniffing bytes. **Before declaring a dependency load-bearing, check whether its expensive part answers a question you have already answered another way.**

## Identity flavours: mise (ITV) vs mise-home (Planet Modha) — a SECOND flavour axis (mise-tatego, 2026-07-12)

Distinct from build flavours above (full/slim = *extraction extras*); this axis is *identity/credential*. Mise ships as two published plugins from one source — **`mise`** (work, `mit-workspace-mcp-server`, `sameer.modha@itv.com`) and **`mise-home`** (personal, `planetmodha-workspace-mcp`). Only these two will ever exist.

**Build topology, three repos, and it is easy to get lost:** `spm1001/batterie-de-savoir` is the suite *source*; `spm1001/batterie` is a *separate, generated* marketplace holding `assemble.sh`; `spm1001/batterie-home` is a *private, generated* marketplace carrying only `mise-home`. Every file in the generated ones is output — **never hand-edit.**

**The flavour transform** (`make-mise-flavour.sh`) is a guarded string substitution over the vendored copy: data-dir, keychain service, rules filename, plugin `name`/`displayName`/`identity`, the mcpServers key, and the skill's `mcp__mise__`→`mcp__<name>__` tool refs — then swaps `credentials.json` and runs a `scan` guard that **fails the build if any ITV-identifying string leaks through**. Why substitution rather than a runtime env axis: **the SessionStart hooks carry hardcoded identity strings and run in the session env, so an `mcpServers.env` block cannot reach them.**

**The gap it exists to close:** the transform differentiates every *plumbing* surface, but left every *model-facing* surface byte-identical — so two same-named "mise" tools coexisted in one session and an unauthenticated flavour's correct no-token warning read as "the *other* mise is broken." The fix is a symmetric `identity` label carried in the **source** `plugin.json`, not in `assemble.sh` — because `plugin.json` is drift-exempt from the ratchet and the assembler vendors mise in a *generic* loop, so special-casing it there would rot. A **field-specific** guard asserts the swap landed, rather than a file scan, so the hook's legitimate sibling reference to "ITV (itv.com)" isn't a false leak. `ensure-mise.sh` reads `identity` once and drives the warning, the rules-shard filename and the skill description marker. A per-result "acting as" cue was **deliberately declined**.

**Per-flavour token stores never cross:** each flavour's `TOKEN_FILE` is `~/.claude/plugins/data/<name>/token.json`, so authenticating one does nothing for the other.

**The harness names MCP tools by INSTALL METHOD, not by server alone — so there are two legitimate prefixes per flavour and the transform rewrites both.** A plugin install yields `mcp__plugin_<plugin-name>_<mcpServers-key>__<tool>`; a bare MCP server in settings or `.mcp.json` yields `mcp__<key>__<tool>`. Plugin name and server key are **independent fields** — `mcp__plugin_compound-engineering_context7__*` proves it — and **hyphens are preserved, with no sanitisation**. So `mcp__mise__*` is not a wrong name, it is the right name for a different install method, which is why the shard and the skill describe the shape rather than hardcoding either form. **Match on the server name INSIDE the tool name; a grep for a hardcoded prefix is a silent zero**, which is how the shard told every session the wrong prefix for four and a half months without a single error surfacing.

**And `allowed-tools` is a permission *pre-approval*, not a restriction** (`disallowed-tools` is the restricting field), so the skill's non-matching glob withheld nothing — it simply granted nothing: a permission rule that silently guards nothing. It was inert on tube only because `settings.json` already allowed the live prefix; on a machine without that line, every mise call in a skill-invoking turn would have prompted.

## Code patterns

- **Folder cues** in `tools/create.py` use a shared `_resolve_folder_cues()` helper; **PDF rendering** is platform-adaptive (CoreGraphics on macOS, pdf2image/poppler on Linux — and poppler's absence is a silent thumbnail failure, mise-releko).
- `get_deposit_folder` **wipes on re-call** — never call it twice for the same folder mid-operation. This is a real retry hazard: don't add automatic HTTP-level retry to fetch in remote mode.
- `MiseSyncClient.upload_multipart()` boundary is UUID-based, because binary uploads could contain static boundaries.
- google-auth `Credentials.valid` only checks local `expiry` — the httpx client retries once on 401 with forced refresh.
- **Heading extraction** suppresses the blockquote prefix when a heading prefix is already present, preventing `> ##` for indented headings.
- **Shadow field masks.** When an adapter defines a constant for API field selection but the call site uses a locally-defined string, mocked tests pass because mocks return whatever you tell them regardless of which fields were requested. The `is_unread` bug was this. **Guard by testing the mask itself (`assert "labelIds" in fields`), not just downstream logic** — any time you see a fields/projection mask in an adapter, verify the call site uses the constant.
- **Driving `run_operation` directly (smoke scripts) requires the FULL param dict** — the DISPATCH lambdas use `p["key"]` access and server.py always passes every key, so a partial dict raises KeyError'd INTERNAL errors that look like handler bugs.
- **An idempotency gate keys on its OWN state, not a proxy.** `configure_call_logging`'s early-return was `if _calls_logger.handlers: return` — a fail-open proxy conflating "any handler exists" with "our file handler is wired." It worked until pytest 9.1's logging plugin injected capture handlers onto the logger, tripping the early-return so the call log never got its `RotatingFileHandler`. **When an "already done?" check tests a proxy for the real condition, check the real condition.**
- **A manifest key is a contract with every consumer that keys on its presence, not just the one you added it for.** Widening `tabs` into single-tab sheet manifests (so `?gid=` could resolve) silently switched `do(create, source=)` onto its multi-tab route, because create detects multi-tab deposits by `manifest.get("tabs")`. The delta happened to be benign — same CSV-import engine, tab name now preserved, pinned with a deliberate-contract test — but nothing would have said so if it weren't. **Before widening WHERE a manifest key is written, grep for everywhere it is READ** (`grep -rn '"tabs"'` cost one minute and was the only thing between "shipped improvement" and "unpinned behaviour change"). Presence-keyed readers make every write-side widening a routing decision somewhere else — and a consumer in *another repo* reading mise deposits meets the same silent rerouting; the manifest shape change (`tabs` always present, entries carry `sheet_id`) is now the contract.

## Field reports outrank synthetic tests

**A consuming agent's own field notes are a spec surface (2026-08-12).** The requirement that hydrated files carry a line-1 `source:` Drive URL came from the Garni spike agent's self-written field handbook — not from any API, doc, or brief — and the worked example's flatten was silently dropping it until that feedback arrived by accident, relayed from the wrong window. When building for an agent consumer, read what the agent tells its successors; the affordances it depends on live there and nowhere else.

When a field report names the file, the lines, the root cause and a fix sketch, it is grounded in real reproduction; existing unit tests are often snapshots of synthetic shapes from one fixture. **If the brief's recommended fix breaks a test, read the test before hunting for an alternative** — usually the test asserts a *more aggressive* version of "correct" and the field report has just shown that aggression eats real content. Update the test to the new contract rather than finding a clever fix that preserves the test's shape. Worked case: a brief said "walk backwards" for signature stripping; that broke a test, so a proximity-window alternative was tried, which preserved the test but didn't fix the standalone-message case. Walking backwards and updating the test was right all along.

**Companion discipline — probe the mechanism before building.** Both build briefs in the 2026-07-22 session were right about the *problem* and wrong or unproven about the *mechanism*: cizuzi's "named revisions" design was falsified in three API calls. A cheap probe — three or four API calls against a purpose-built throwaway fixture — beats any amount of design-from-docs, and the fixture keeps paying: one Firework-lyrics doc served as repro, test fixture, demo stage and smoke target across three releases. Build the tiny fixture; probe the mechanism; only then design.

**And the cheapest layer of that ladder is the Request-union grep, which settles both directions before any code (2026-08-09).** For "can API X do Y?": fetch the CURRENT reference for the batchUpdate request union via mit-google-devdocs and grep it. insertRichLink's presence (Docs) and absence (Slides) each cost one call, both contradicted training memory, and the union names EXACTLY what can be attempted — no invented request name survives schema validation. Pair a negative with one live 400 control ("Unknown name … Cannot find field") to prove the doc isn't stale; pair a positive with a write+read-back probe, because field-level contracts (title refused, server-enriched) live below the union's visibility.

**And the same discipline applies to shipping a heuristic: its false-positive rate is a measurement, not a design property — and in this repo the measurement costs one probe script.** `get_sync_client()` + the Gmail API against the authed mailbox gives a live corpus in ~20 lines (`category:promotions OR category:updates` for notification-shaped mail); run the candidate predicate over real payloads BEFORE shipping, and keep the known true positive (thread 19fb9faca1565748 for data tables) in the loop as the must-still-fire control. The first `has_data_table` shipped on design intent and measured **31/40 wrong** — live in the marketplace for ~40 minutes; the recalibration measured 0/35 before it shipped (2026-08-08). The tell in prose: writing "accepted false positive" without a number attached — that phrase should trigger the probe.

**Operational corollary:** this repo is public and Sameer commits to it directly — `git fetch && git log HEAD..origin/main` before starting.

## The token sequence is the deposit's real interface (2026-08-14)

A deposit exists in three forms — the rendered page a human sees, the plaintext bytes we inspect, and the token sequence the model consumes — and the third is the interface, with human legibility a bad proxy in BOTH directions. Measured in one night: markdown pipe tables (the format everyone would call "highest quality for an agent") cost 23–27% MORE tokens than pdftotext's whitespace-padded columns and bought zero comprehension gain on a hard-table eval (8/8 everywhere, 2 readers × 2 formats) — the padding everyone calls janky compresses to nearly nothing because BPE eats space-runs whole while `| --- |` furniture fragments. Two corollaries. First, **when considering swapping a pipeline's primary component, run the incumbent's own quality instruments over the challenger's output before deciding**: the flattened-table detector — calibrated on markitdown's failure shapes — fires on poppler's perfectly-good output, so a naive primary swap would have routed every table-heavy PDF to the slowest path; a calibrated detector measures distance from its training distribution, not quality. Second, **token counts do not travel across tokeniser families** (BPE vs SentencePiece differ most exactly at whitespace), so tonight's cl100k numbers must be re-measured per consumer model family before informing policy — Garni is Gemini, i.e. SentencePiece. The extractor axis is now settled by the census (below); **the deposit-format policy LANDED 2026-08-18** (`docs/2026-08-18-deposit-format-policy.md` — every verdict with its deciding number, and a `Depends on:` line citing per-rig profile facts in `~/notes/practices/model-profiles/`); mise-rolira closed with the 918-run league behind it (findings: `~/notes/practices/mise/format-league-findings.md`; evidence archived beside it). mise-mitoki carries the implementation plus the policy's vendored ride-alongs (raw numbers live on those briefs); mise-jopohi carries the vision lane (anchors + crops, interlocked with Garni's agsp-cigene); mise-hihohu carries the smevals trial (banc already runs smevals — read banc's README before touching the battery).

**The census settled the extractor axis by measuring our own corpus, and the method outlives the verdict (2026-08-17; findings `~/notes/practices/mise/census-findings.md`, data `census-2026-08-17/`).** A published benchmark rank is a hypothesis about your corpus: READoc puts docling at 58.8 and markitdown at 35.2, yet on 70 of this estate's real PDFs docling came LAST — 75.7% verbatim survival against pdftotext's 97.4% and markitdown's 93.0% — because its layout model classifies text regions of hybrid decks as pictures and emits `<!-- image -->` placeholders, discarding text layers that were good all along, at 17s/slice and a 5.4GB torch venv. That failure is structurally invisible to leaderboard metric families — they score what the parser produces, never what it silently dropped — which is why "adopt before build" must end with local verification, not with reading the table. The counter-instrument is cheap and reusable: mint exact-value presence probes from rendered pages (fan the reading out to fresh-context agents, ~5 probes/page), score by substring against each extractor's output, and spend the lead's own eyes only on all-miss and disagreement rows — after a typography-normalised matching pass (curly→straight quotes, unicode spaces), because roughly a quarter of apparent all-misses were byte-form drift. The drift is itself a standing fact: **extractors change typography even when extraction is perfect, so any verbatim ⌘F contract on deposits needs normalised matching.** Corpus facts the policy leans on: 53% of sheets past the 500-row crossover, PDFs 78% born-digital / 21% hybrid / 1% glyphless. Two operational residues: the harness killed a ~53-minute background grind with no OOM and no error trail — treat ~50 minutes as the planning ceiling for background tasks until measured, and design resumability (skip-completed-rows on rerun) into any long sweep from the start; and `~/census-work` (~2GB) plus `~/.venvs/census` (5.4GB) are working assets for rolira's bench re-adjudication, not litter — tidy deliberately after the bench runs.

**When a filter needs a semantic judgement a deterministic system cannot make, change the contract instead of approximating the semantics (mise-jopohi, 2026-08-18).** The crop filter needed "is this a chart?", and two plausible proxies were each measured against the census's 20 adjudicated vision-only probes before shipping — the only reason neither survived: excluding JPEGs (photos are usually JPEG) evicted a real chart that shipped as JPEG, and a count cap (photo decks are noisy) evicted the same chart again by ranking it behind forty photos. What shipped is pure geometry — size, page-spread, page-coverage — which keeps some logos and photos, plus a contract line in `skills/mise/references/deposit-structure.md` telling the vision-capable consumer the semantic call is theirs. False positives cost kilobytes; a false negative is a silently lost value. Same shape as the never-narrow-a-fetch rule, arrived at from the opposite direction.

**The extraction-lane differ is a reusable instrument** (`~/notes/practices/mise/showpiece-triptychs-2026-08-18/build.py`): ghostscript's `-dFILTERIMAGE -dFILTERVECTOR` renders "what pdftotext can see" as an image, pdfminer's LTImage bboxes place the embedded objects, and compositing the two gives a visual diff of any page's text lane versus its design layer. It found a false caption of its author's within an hour of existing (the live verdict list contradicted the prose). Two operating notes: on dark decks, white glyphs render white-on-white once the background image is stripped, so the glyph panel UNDER-shows survival — pdftotext itself reads them fine; and when a panel would be identical to its neighbour ("nothing to restore"), ship what the system actually does instead (the stamped fallback) — an unchanged panel reads as a bug, never as a boundary. Standing caveat: build.py imports mise's private `_select_crop_objects`, so a filter refactor breaks regeneration silently — a demo fault, not a mise one.

## The competitive bench (mise-zidipo) — the artefacts and the instrument traps

**The bench is real now: design note v0.3 at `~/notes/practices/mise/workspace-mcp-bench-design.md` (recovered from a claude.ai chat — it existed nowhere on disk), Tier-0 findings at `~/notes/practices/mise/tier0-findings.md` with inputs in `tier0-2026-08-17/`, and the §5 fact-recall harness (`fact_recall.py` + `bench-corpus/`, FIXTURE-01 in planetmodha My Drive, mise 5/5 on the control run).** Sameer's purpose steer — diagnostic first, waterproof not bulletproof — cut the mutation family and reordered the design. Governing rule, §7.1: **Tier 0 is never publishable as a standalone ranking** — it flatters the hosted-gateway architecture by an enormous margin. And Google's harvested schemas date from 2026-08-01 against preview servers under active development: re-harvest before publishing any comparison. The PDF census (above) turned out to *be* §5 run on a different unit under test — §5.2 of the design note.

**When a measurement decomposes a whole into parts, publish the residual.** One subtraction, printed as a column, caught two separate instrument bugs in an afternoon: an `outputSchema` omission that left three quarters of a tool definition unmeasured, then an SDK field-name trap that scored 121 richly-typed schemas as zero — the MCP Python SDK emits its own field names (`input_schema`) rather than the wire's (`inputSchema`) unless asked for aliases, and *which you get depends on the SDK version the harvester resolves, not on the subject under test*. Both were dangerous for the same reason: **the totals stayed correct**, computed from the whole object, so nothing looked broken and the second bug was biasing a competitive result toward a rival on the exact metric under test. A split whose parts don't sum to the whole is the only warning available, and it is free. (Also proposed for the always-loaded corpus on `~/.claude`'s board.)

**And a borrowed-frame variant the usual guard misses: an instrument from your own estate, written the same morning, by a session whose findings you already trusted.** Two "relaxed" scoring folds now exist here with different semantics — rider's is numeric-only, fact_recall's is numeric+typographic (a strict superset) — and the shared *name* is the trap. A session read "two-column verbatim/relaxed scoring" and "6 probes lost to typography drift" a paragraph apart in one fresh document and fused them into a causal claim that the relaxed column caught the drift; it cannot, being numeric, and those cases were adjudicated by eye. **When borrowing an instrument, re-derive what its columns compute rather than trusting what its findings say** — freshness is no protection and may be the opposite.

**Score independent candidate representations, never one merged pot — the format league's scorer lesson (2026-08-18).** A verbose reader answers a set-question three ways in one reply: a headline sentence, a workings table with verdict columns, a hedge paragraph ("if you meant met-or-exceeded, X joins"). The league's scorer originally accumulated every region-mention into one set and failed in BOTH directions: mention-sweeps counted the "No" rows of workings tables (verbose-but-correct scored wrong), and when the affirmative regex widened, one stray line ("London came closest to overtaking…") poisoned an otherwise-exact list (correct regressed to wrong). The fix is structural, not lexical: each coherent representation — each headline line, each header-plus-block, the verdict-row sweep — yields its OWN candidate set, and the answer is correct if ANY candidate matches expected. Two answers still resisted (header and table split by a narration line) and went to a hand-adjudications file citing what was read — deliberately, because prose-tolerant block scanning is where over-acceptance starts. Companion finding from the same league: **the biggest levers sat beside the variable under test, not on it** — seven formats were benched, and the two effects that dwarfed every format difference were single sentences the harness held constant in the prompt (show-your-working: 8 computation misses → 364/364; the disclosure rider: 0/84 → 42/42). When an eval's arms all tie, look at what the harness holds constant.

## Session hygiene: a restart re-presents a stale handoff

A mid-session restart re-fires the SessionStart hook, which re-presents the most recent *written* handoff — and that handoff can describe a world the same session has since worked past (observed 2026-07-19: the hook said "two items remaining" while the board was already empty). At any restart, reconcile the hook's picture against `git log` + `bon status` before believing it — a handoff is a snapshot of when it was written, not of the session that wrote it.

## Committing board state: "stage the paths you edited" is not enough

**This board is Dolt-backed** (`.bon/doltbackend` is present; `items.jsonl.backup` is a pre-migration ghost that bon ignores). Two consequences, and they point in opposite directions.

**The Dolt inversion: work you genuinely did leaves no git trace here.** A `bon new` or `bon done` on this board writes to the Dolt server, not to a file — so "my commit contains nothing of mine" can be entirely correct on this repo and still deserve a second look. Don't reason from an empty `git diff .bon/` to "my board write failed".

**And on any *JSONL*-backed board in the estate, the estate-wide rule against `git add -A` in live-config repos is insufficient rather than merely inconvenient** — learned the hard way on 2026-08-04, twice in one session, with only the second caught. That rule assumes one file per concern; an append-only JSONL board breaks the assumption, because the path you legitimately edited is the same path four other lanes legitimately edited. Following the guard to the letter — staging exactly the one path you touched — still produced a commit whose message named a CI bug and whose entire diff was another session's unrelated documentation. **The discriminator is one command: count the item ids in the diff and compare against the ids you minted.** The deeper shape is worth more than the instance: *a sufficient-looking guard suppresses the very check that would catch its own gap*, because a reader who has followed it believes they are done. Proposed as a `traps.md` row in `carte-ralicu`, with a note that it may deserve a render at commit time rather than prose — prose being exactly what goes unread at the moment of action.

## MCP Resources: what they're for

Mise ships eight FastMCP Resources — six static docs (`mise://docs/*`), one live API call (`mise://gmail/labels`), one parameterised template (`mise://tools/{tool_name}`). Two empirical behaviours: **parameterised templates are invisible to discovery** (listing returns only the seven concrete URIs, though a hand-constructed URI resolves fine), and **content comes back inline**, so cold-fetching content via a Resource dumps the whole payload into context.

**The right division of labour:** Resources for small live introspection (labels, drafts, quota); `fetch` for content acquisition; native filesystem read for steady state. The URI scheme is **not** load-bearing. Generalisable: when a layer X exists "because of Y" and Y gets cut, audit X — it usually goes too.

## The apps-script/ subsystem — one trap worth the whole section

The trigger went dark for roughly four months with no disable-email, no log and no error, while mise's own production client in that same project was untouched throughout. The deleted client was not restorable. It surfaced only when a manual re-arm returned `Error 401: deleted_client`. **Before rotating a project's OAuth credentials, audit what else authorizes through it. A dead time-trigger emits nothing observable; only the product reveals it.**

Two operational facts that cost a session each: **a CLOCK trigger can only be created AND deleted from the Apps Script editor** (triggers created from a `scripts.run` execution complete without error and are silently dropped, and the CLI's `triggers list`/`delete` are blind to editor-created ones); and **`itv-appscript run --dev` executes SERVER HEAD, not the local code you are reading** — `pull` and diff first.

What gets rescued each time is something the *plan* would have deleted — the Google managed-MCP finding survived the 2026-08-02 pass only because it postdated the plan that would have cut it. **A compaction plan is itself a borrowed frame: re-check it against the board before executing it.**

**Generalises to any pruning task — dead code, unused config, stale fixtures, backlog triage: the work queue is the oracle, not the artefact.** Every criterion for deletion is really a claim about what future work will need, so the instinct to read the artefact harder is the wrong instinct; read the queue before you read the thing. A plan *about deletion* is the most dangerous kind of borrowed frame, because its failures are invisible by construction — nothing goes red when you delete the wrong thing.

**Two seams learned 2026-08-04, when a pass netted UP before it netted down.** First, **cut where this file duplicates a globally-loaded corpus**: the verification residue here had grown into a repo-scoped second copy of `~/.claude/context/verification.md`, which loads every session anyway, so what earns space is only the *repo-specific* edge — the autouse stub that makes assertions vacuous, which of the two instruments sits upstream of the caller, the two import-path divergences. And expect the arithmetic to fight you — the session running the compaction is usually the session that just learned something worth keeping, so budget to cut roughly twice what you add.

## Gmail: the code's actual shape

*The paragraphs below are the only place this file describes how the Gmail path actually works, and every claim still matches code. They spent months buried under a "Current state (June 2026)" heading whose own caveat told readers to discount them — rescued 2026-08-02. For what shipped when, read `git log` and the board.*

**Body selection is plain-text-first with one measured exception, and the policy lives in `html_convert.py::select_body_text()`, not the adapter.** Structure-discard is one disease with many hosts: Outlook's auto-generated text/plain flattens tables before mise ever sees the message (fingerprints of the plain part: `*` bullets with two-space indent, `<angle-bracket>` URLs, `[cid:...]` placeholders); our own HTML cleaner once did it by deleting empty `<td>`s (dropped — cost asymmetry: a kept spacer is cosmetic, a deleted data cell is silent corruption); markitdown does it to PDFs two ways, split-flattening (loud) and delimiter-stripping (quiet — rows become plausible sentences of numbers, and the discriminating fact is that prose writes figures with unit suffixes, "£3,214m", while tables write them bare, "3,214" — detector in `extractors/text_quality.py`). The quiet variants are the dangerous ones. The stripped-row signal was recalibrated against the real FY2025 annual report (mise-hasati, 2026-08-08): the ship-time end-cluster alone measured 75–84% on table-dense pages (the bakeoff's plain signal hit 86–98% but false-fired on a third of table-free pages); the shipped two-clause form — end-cluster accepting nil markers (`–` is a cell value), OR a run of ≥4 consecutive bare/nil tokens (prose interleaves words between figures; address directories decorate theirs) — measures 86–100% with zero prose/TOC/address false fires. Corpus lesson for the next recalibration: **the ground-truth column has an instrument too** — pdfplumber's ruling-based `extract_tables()` misses borderless grids, so "fires on a table-free page" needs eyeballing before it counts as a false positive (all six such fires were real tables). Before scoring a detector against any ground-truth column, ask what the ground-truth instrument itself cannot see. So when a multipart message's HTML holds a FLAT data grid (`has_data_table`: no nested table, ≥2 rows of ≥2 text-bearing cells — both structural requirements load-bearing, see the 31/40 measurement above), the body comes from converted HTML instead, always disclosed in cues; it never fires in slim builds.

**Signature stripping walks *backwards* from end-of-body**, because forward-walking false-positived on benign short text where URL density bled up from quoted Outlook replies below. `strip_signature_and_quotes` returns `(body, warnings)`. **Apple-Mail-style bare-name lines survive stripping by design** — under-stripping is safer than eating content, so "mise didn't strip Alice's name" is the trade, not a bug.

**The catastrophic-strip revert (rejula) is the guard that matters, and its dual condition is deliberate.** A >80% warning wasn't enough: a strip could eat the whole message and merely flag it. mise now **reverts to the pre-strip body** when a strip BOTH keeps <35% of the original AND removes >1000 chars absolute — mechanism-agnostic, so a legitimate compact-sig strip on a short reply is protected by the absolute floor while a body-eater on a long message is caught by the ratio. The culprit was `_strip_trailing_contact_block`; talon was exonerated, it only scans the last 11 lines. **The call log is blind to this whole class** — a content-eating strip logs as a clean `ok`. Stock-taking finds the *fumbles*; only field reports find the *silent* failures.

**Two header-level traps, both live.** `_parse_headers` canonicalises header-name case (RFC 5322 — Outlook emits `CC:`, which an earlier case-sensitive filter silently dropped, starving cc lists AND participants), and `do_reply_draft` passes `current_user_email()` into reply_all inference so self-exclusion actually fires. Participants walk From+To+Cc+Bcc across all messages (`_extract_participants`, deduped on canonical email with the best display form), and **Outlook's `application/octet-stream` mis-tagging is recovered by filename extension** (`_resolve_attachment_mime`) on both the attachment-fetch and eager thread-fetch paths. .docx fetches warn when Word markup was flattened: `extractors/docx_markup.py` counts w:ins/w:del/comments/inline-images by **regex on bytes, not an XML parse — email attachments are untrusted input and regex can't be entity-bombed**.

**File layout after the wugehi split:** `tools/fetch/gmail.py` holds two orchestrators; the three concerns live in siblings — `gmail_participants.py`, `gmail_exfil.py`, `gmail_attachments.py`. `classify_attachment()` in gmail_attachments is the **single source of MIME→category dispatch** (it was triplicated and drifting). Test patch targets for the moved helpers point at `tools.fetch.gmail_attachments.*`; the `tools.fetch` facade keeps all public imports stable.

**Forms, and the recipe for a new content type.** `do(create, doc_type='form')` is structurally unlike every other create path — two API calls on `forms.googleapis.com` rather than Drive's `files().create()` with media upload — so it branches early in `do_create`, before any Drive-centric logic. Two live gotchas: **item titles cannot contain newlines** (400 "Displayed text cannot contain newlines"; `_split_title()` splits multi-line YAML block scalars into title + description), and form descriptions render as plain text, so bullets appear literally. The recipe a new content type follows: add scope, adapter, extractor, wire the elif in the router, update the three MCP resource strings and this file. That last step is easy to forget **because omission causes no test failure** — it just leaves future Claudes unaware the capability exists.

**Google API error bodies are lost in `raise_for_status()`** — it throws before the body can be read, so bypass with a raw `httpx.Client` call when debugging. Tracked as mise-wipopo.

## Cowork & Desktop integration

**Cowork is Claude Code in a VM with `~/.claude/` swapped for a session-scoped temp dir.** An uploaded plugin is staged into `CLAUDE_CONFIG_DIR` and CC's standard machinery does the rest — plugin loader, `SessionStart` hooks, stdio MCP spawn — all on the **Mac side**, unchanged from native CC. So one `.claude-plugin/plugin.json`-shaped bundle serves both. **Diagnostic implication: when something doesn't land, the failure is in the Mac-side spawn, not in the VM** — and don't conclude failure from one early snapshot, the stdio handshake takes seconds.

**tube carries TWO independent plugin registries, and they update separately.** Plain CC reads `~/.claude/plugins/installed_plugins.json` (updated by `/batterie:update`); Claude Desktop's local-agent-mode reads its own per-session registry under `~/.config/Claude/local-agent-mode-sessions/…/rpm/plugin_*/`, at possibly-different versions, which `/batterie:update` does **not** touch. **Before concluding a plugin's install state or version, check the registry the current session actually runs under** — the tell is where your loaded instruction-shard paths resolve. This is how a confident "mise-home isn't installed on tube" was wrong: it *was*, in the other registry, at a newer version.

## UX patterns: friendly error wrapper

When an external dependency (OAuth token) is missing, the tool's error response includes a *concrete in-app remediation pointer* — not a CLI command, but the name of another tool the same Claude can invoke. The remediation tool spawns a detached subprocess so the MCP call returns immediately with a URL inline as fallback. The data self-discloses; Claude reads the error, finds the remedy verbatim, calls it.

This pattern showed up twice in the 2026-05-04 install sweep: (1) `mise.do(operation="setup_oauth")` invoked because the error message named it, and (2) the multi-Workspace-connector ambiguity that became the `cues._identity` polish bon. **General principle:** prefer self-disclosing data over instructional copy. Skill copy may not be read; data attached to a response always is.

## Google's managed Workspace MCP servers — the live strategic fact (probed 2026-08-01)

Google now runs its own managed MCP servers, one per product, at `{gmail,drive,docs,sheets,slides,calendar,chat}mcp.googleapis.com/mcp/v1`, with a cross-corpus `workspacemcp.googleapis.com/mcp/v1` on top — Cloud Next '26 developer preview, auth terminated by `accounts.google.com`, RFC 9728 metadata live. Anthropic's built-in Gmail and Calendar connectors were **re-platformed onto them**: `gmail.mcp.claude.com` and `gcal.mcp.claude.com` are now dead hostnames (CNAME residue, TLS unmapped, verified against a live control), while `microsoft365.mcp.claude.com` still serves — so the Anthropic-proxy fleet persists only where the provider has no managed MCP of its own.

**The consequence that matters: Google's servers accept ANY OAuth client.** The ITV gate on the built-in connector is that it authenticates with *Anthropic's* client, which ITV app access control blocks — but an ITV-Internal client, which is mise's exact trick, pointed at Google's hosted servers is a zero-infrastructure sanctioned path. That is what makes mise-mawawa possible as configuration rather than hosting, and it is why the remote-deployment path above is superseded.

Measured strengths and weaknesses, from the bench (`docs/2026-08-01-google-mcp-spike.md`). **They win** server-side relevance ranking of Gmail — the one capability mise structurally cannot build, because rankers live with indexes and the Gmail API exports a filter with no ordering parameter — and calendar recall, 4/4 against mise's 0/4 on the ±7d window. **Mise wins** payload economics (2KB against 205–264KB), metadata (their results carry no timestamps, labels or unread state), and honesty. So the evidenced design is a hybrid: their ranker for candidate *discovery* inside mise's envelope, hydrated with mise's own metadata and deposited as usual (mise-gofuvu).

**Their surface measurably accepts-and-drops, so consume it the way this repo would want to be consumed.** `pageSize` is ignored, pagination is phantom, `includeComments` is a no-op, and their `update_values` writes no `chipRuns` and no `textFormatRuns` — so rich-text and smart-chip writing does not exist there either, and routing Sheets link work through them does not cover what mise-bazuvo actually wants. Re-derive rather than trust: count their items yourself, stamp your own timestamps, hydrate metadata via mise's own APIs, and cue any divergence between their contract and their behaviour. Exercise every parameter with an observable-effect case before relying on it, and re-probe on preview churn. Pre-GA terms forbid customer-facing use; personal and team use is fine.

## The release ratchet — how not to wedge the marketplace

Mise reaches users through the single assembled marketplace `spm1001/batterie`, which vendors mise's **full runtime source** because mise declares `mcpServers`. The vendor boundary is **wider than runtime code**: `CLAUDE.md`, `README.md`, `CHANGELOG.md`, `skills/`, `pyproject.toml`, `uv.lock`, `instructions.md`, `credentials.json`, `hooks/` and `apps-script/` all ride along. **The ONLY free-to-commit-unbumped trees are `tests/`, `docs/` and `.bon/`** — a "docs fix" to CLAUDE.md is ship-coupled, not free. Versioning is suite-managed, so mise's own `plugin.json` version is local-dev-only: release via `/batterie:publish`, never hand-bump and never hand-run the assemble.

**And that boundary is a design input, not packaging trivia: where a guard lives sets what it costs, so choose its home BEFORE sizing its worth.** gaseve looked publish-shaped ("mise's shipped guidance needs a checker") until the vendor boundary reframed it — in `scripts/` it would ship to every user (the capture_fixtures.py mistake again); in `tests/` it ships nothing, costs no suite bump, and runs on every push anyway. Checking which side of the boundary a feature can live on can move it from "needs a release" to "just commit it", and that check belongs at the start of sizing, not the end.

**The ratchet fires on content-changed-at-unchanged-version, and it has two triggers.** The obvious one is a hand edit to vendored content. The other: **a Dependabot merge is a vendored-content change**, because `pyproject.toml` and `uv.lock` are vendored — so publish a patch after one merges rather than leaving it for the 07:00 UTC cron. The tell before it bites is shipped `plugins/mise/pyproject.toml` diverging from `main`.

**An auto-merged Dependabot commit gets NO `CI` verdict on the merged state, and this is silent.** `ci.yml` triggers on `push` to main, but GitHub does not fire workflows for pushes made with `GITHUB_TOKEN` — so the auto-merge produces `CodeQL` and `Dependency Graph` runs and **no `CI` run at all**. The PR-ref run is the only test evidence, so **the tested tree is the PR head, never the merge result**: fine while main moves slowly, wrong the moment two dep PRs merge in sequence. Control: after any Dependabot merge, run the suite locally before believing main is green (three bumps on 2026-08-04 came out clean at 2,110 passed — a mechanism finding, not an incident).

**And `mcp[cli]>=1.28.1,<2.0.0` is held for a different reason than its comment claims.** The comment says "structured returns and tasks support"; there is **no Tasks code in this repo at all**, and the entire consumed surface is three imports — `mcp.server.fastmcp.FastMCP` in `server.py` and `resources/docs.py`, `mcp.client.stdio` in `scripts/smoke_stdio.py`. **2.x moves or removes `mcp.server.fastmcp`**, measured from Dependabot PR #25's CI failure, so the bump is a port of the registration shim rather than a version change. Full evidence on `mise-kofoba`.

Two reflexes from the day the shared bus went down. **(1) When a marketplace publish fails, check whether a *sibling* repo is the cause before hunting in your own** — one unbumped edit elsewhere blocked every plugin for hours. **(2) A bump clears the ratchet regardless of which content changed, so the fix working does not validate the causal story.** A wrong cause propagated through three artefacts that day before substrate-checking corrected it.
