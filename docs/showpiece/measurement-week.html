We stopped guessing how AI reads our documents

Every AI workflow we run starts the same way: a document becomes text, and a model reads it. For a year we ran that step on folklore — plausible beliefs about which converter is best, which format models prefer, when they need a database engine. In one week in August we spent a few hundred dollars of API time replacing the folklore with measurements. Six findings. Every one of them contradicts something we'd have confidently written down a fortnight ago.

1. The published leaderboard inverted on our corpus

The parser-benchmark literature says docling is the class act (READoc scores it 58.8 against markitdown's 35.2). On our 70 real PDFs it came last — 75.7% of probed values survived extraction, against 97.4% for pdftotext, a twenty-year-old command-line tool. And it failed in the treacherous direction: its layout model classifies text regions of hybrid decks as pictures and throws away text layers that were perfectly good, at 17 seconds a slice with a 5.4GB install. The humble tool won on every document variant and runs 55× faster than the incumbent. A benchmark rank is a hypothesis about your corpus, not a fact about it — adopt-before-build has to end with local verification.

2. We benchmarked seven formats; the winners were two sentences

The format league asked which deposit format — CSV, aligned text, markdown tables, minified JSON, and friends — models read most accurately. Answer: with one condition met, they all tie at ceiling. The two biggest effects we measured all week weren't formats at all. Telling a tool-less model to "show your working in text" took Gemini Flash from 8 computation misses to 364/364 — every previous miss flipped correct, with visible arithmetic. And a one-line disclosure instruction (below) took it from never mentioning corrupted data to mentioning it every time. We went in to benchmark formats; the levers were sitting beside the formats, in the prompt. (One format did lose: minified JSON costs up to 40% more tokens on Gemini's tokeniser — up to 64% on Claude's — and recruits slower methods. Banned.)

3. The model that fixes your data without telling you

We planted sabotage: a spreadsheet whose header row lies about its columns. Gemini Flash silently repaired it — worked out the real mapping from the data, answered correctly, and never once mentioned the headers were wrong. Zero disclosures in 84 runs. From the outside, its silent-right is indistinguishable from its silent-wrong, which is the worst possible property in an unattended pipeline. One sentence in the system prompt — flag internal inconsistencies prominently — took disclosure to 42/42, and the control (a clean twin of the file) raised no false alarms. That sentence shipped into Garni's production prompt the same day.

4. Nobody used the fancy engines

We'd half-written advice telling AI analysts to use DuckDB or Polars for big files. So we installed both and watched what tooled Claudes actually chose, on tasks up to 50,000 rows: awk, grep, jq and stdlib python — every single time. Engines: zero uses. Results: 18/18 correct at 31–85 cents a run. The advice we nearly shipped named tools its readers demonstrably don't reach for. (DuckDB keeps a when-clause for sustained multi-query analysis and joins. The when-clause is doing a lot of work.)

5. Hints work at eye level, and nowhere else

Same routing hint, word for word, in two places: inside manifest.json, and as a README beside the data. The manifest version was read in 15 of 20 runs — and obeyed in zero. The README version changed behaviour in 4 of 10. Position alone was worth +40 points of obedience. Metadata is where eyes go for orientation; text at eye level is what changes hands. This one now shapes everything we ship: routing guidance goes in the response a model actually reads, never in a metadata field we merely hope it honours.

6. Models are now rigs we qualify, not vibes we trust

All of the above is per-model, per-harness — Flash needs the working-shown sentence, Claudes disclose sabotage unprompted 7 times in 8. So the week's findings are filed as datasheets per rig (model + harness + prompt), with a re-runnable battery that takes a new model string. When Gemini 4 or the next Claude lands, we don't re-litigate opinions: we spend an afternoon and ~$50, re-run the battery, and read what actually moved — and every policy that depended on the old numbers names exactly which facts it depends on.

What changed in the tools, because of this

  • mise, since suite 1.67.0 (18 August): pdftotext is now the PDF extraction primary — best fidelity on every variant we measured. And because ~3% of values in real PDFs exist only inside chart images (concentrated in chart-heavy conference and research decks), PDF deposits now extract embedded charts as image crops, each announced by a grep-able anchor in the text at the exact page — so a text-first reader knows where the pixels are, and a vision-capable one goes and looks. Garni's retrieval loop is being built to consume exactly this.
  • Garni's production prompt carries the measured disclosure sentence; the show-working sentence is filed to follow it.
  • The deposit-format policy is written down with the deciding number beside every verdict, and a dependency line naming the per-rig facts that would invalidate it.

The meta-finding costs one line: measurement beat opinion every time we tried it, and the biggest effects were never where we were looking.
