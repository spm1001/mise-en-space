## For Claudes to come

**All four bugs fixed today were one bug wearing four costumes: a value accepted and then silently dropped.** `nextPageToken` never requested, so never sent. A zero-match `replace_text` shaped exactly like a successful one. Drive syntax keyword-searched instead of executed. `raw_query` discarded on the remote path. None had ever been reported in a year of use, and the reason is the same in every case — **each one produced confident, plausible output.** A crash gets reported; a wrong answer that looks right gets believed and built on. One of these put a false structural claim into a regulatory filing record.

Two working rules fall out. **When a parameter or a signal *can* be ignored, make the ignoring loud** — refuse, or cue, but never accept-and-drop. That principle decided four separate design calls today: refusing Drive syntax in `query` rather than searching for the operator words; `NO CHANGE` rather than a success-shaped payload; cueing a URL's `gid` rather than silently scoping to it; threading `raw_query` into remote rather than letting it evaporate. **And assert on the artefact, not the intermediate.** The one defect that shipped today did so because its test checked the label I'd set correctly while the deposit filename — the thing a human actually sees — stayed `search--untitled`. It was caught by reading real output, not by any test.

A corollary for this repo specifically, because it recurred twice in one day: **a passing test proves nothing until you have watched it fail.** `test_edit.py` autouse-stubs `capture_restore_point` to `{}`, so any "no restore point" assertion there is vacuous by construction. Both times, reverting the production line and confirming red — while a deliberately-added positive control stayed green — was what turned a green tick into evidence. Budget the extra two minutes; it is the cheapest verification in the toolkit and the easiest to skip when everything is working.
