## For Claudes to come

**"Stage the explicit paths you edited" is not sufficient protection when the artefact is a shared append-only file, and following the guard to the letter still produces the fault it exists to prevent.** The estate's rule against `git add -A` in live-config repos assumes one file per concern. A JSONL bon board breaks that assumption: the path you legitimately edited is the same path four other lanes legitimately edited. It bit twice in one session and only the second was caught. Filing `bds-gebaza` in `batterie-de-savoir`, a `git add -A .bon/` produced commit `436f123` whose message names a CI bug and whose only diff is another session's documentation of the `someday` field — my own board write went to Dolt and appears in no commit at all, so the commit is *entirely* someone else's work under my message. An hour later, filing on `~/.claude`, `git diff .bon/items.jsonl` showed five new item ids where I had added one. The discriminator is one command — count the ids in the diff and compare against the ids you minted — and the deeper lesson is about *how a sufficient-looking guard fails*: the existing rule reads as complete, so it suppresses the very check that would catch its own gap. Proposed as a `traps.md` row in `carte-ralicu`, with a note that it may deserve a render at commit time rather than prose, since the prose is exactly what goes unread at the moment of action. **The Dolt inversion is worth holding too**: on a Dolt-backed board, work you genuinely did leaves *no* git trace, so "my commit contains nothing of mine" can be entirely correct and still deserve a second look.
