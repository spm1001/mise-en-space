## For Claudes to come

When a repo's main working tree holds a *sibling lane's* uncommitted WIP, the isolation options rank differently than usual: worktrees are off the table by our own trap row (`git worktree add` can eat uncommitted changes, and the WIP isn't yours to commit first), so a throwaway local clone (`git clone <local-path> /tmp/x`, remote re-pointed at GitHub) is the clean room — full suite runs, explicit commits, push from there, delete after. The companion hazard it dodges: `/batterie:publish` stages `git add -u` in the content repo, so publishing from a tree carrying anyone's uncommitted tracked edits ships them under your message.

And a publish-family mechanism worth keeping: the assemble run ships every flavour of a multi-flavour plugin, but until 2026-08-24 the pull phase updated only the plugin named on the command line — so mise-home's local install fell five releases behind mise with zero signal, because the flavour that lags is by construction the one nobody is sitting in front of. The fix lives in publish.py's `FLAVOUR_SIBLINGS`; the general shape is the stale-negation lesson again — a cost paid continuously and invisibly by someone not in the room. Look for the tax, not the crash.
