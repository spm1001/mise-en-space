### The falsifier drove the whole design

Sameer's `--badly` was *"we mishandle weird comments and markup like those imported from MS Word"*, so the test corpus is not native Docs. Two `.docx` packages were built as raw OOXML and pushed through Google's own converter, and a fixture was cut from the result (`fixtures/docs/word_import_tracked_changes.json`). Building the source by hand mattered: a fixture invented in the shape I expected would have measured my expectations, and the converter is the thing under test.

What that bought, none of it guessable:

- **Word tracked changes really do become Docs suggestions** — `w:ins`/`w:del` → `suggestedInsertionIds`/`suggestedDeletionIds`, with the delete/insert pair sharing ONE id, which is why they render as `{--twelve--}[s1]{++fourteen++}[s1]` and why accepting `s1` folds both halves. The whole fold lane rests on this and nothing documents it.
- **Imported suggestion ids are spelled differently**: `suggestIdImport<uuid>_N`, not the native `suggest.<hash>`. A passthrough matching only the native spelling refused a perfectly valid id on exactly the documents this card is about. Caught by the fixture-backed test.
- **A Word comment arrives anchored to `kix.cmt0` with no `plainTextQuote`** — an anchor id with no anchored text beside it.
- **The headline.** On an NBSP-joined import, a suggested replace with ordinary spaces returns HTTP 200, `occurrencesChanged: 0`, `NO_UPDATES_REQUESTED`. Nothing created, nothing to review — and the caller has been told a change is sitting in the document awaiting a human. Under a direct edit that is a cue the estate has long known about. Under `suggest=` it is a lie, so it now raises, and checks the NBSP spelling before reporting the miss.

### Two rounds of being wrong, both caught by looking at the document afterwards

**My own live run reversed one of my guards.** An edit over text already inside a pending suggestion COALESCES into that thread and returns no new id. My first implementation raised on an empty `createdSuggestionIds` — which is the *inverse* error and worse than the one it guarded: the caller is told nothing was created while a tracked change really is pending, and a retry double-applies. The response said one thing; reading the document said the opposite.

**Then the essayeur refuted the whole thing on both axes.** Four findings:

1. **`do(append, tab='T', suggest=True)` committed a real, unreviewed edit and reported success.** The tab branch `return`ed before the suggest guard ran. *A guard placed after a return is not a guard* — and the suite could not see it, because the downgrade tests varied only mimeType. This is the exact inversion the module's own docstring says must never happen, confirmed live with a read-back showing the smuggled text committed.
2. **A Word `w:rPrChange` becomes `suggestedTextStyleChanges`**, a field the suggestion walker never reads. A style-only import therefore rendered nothing, cued nothing, and mise stated *"0 unresolved suggestions"* about a document Google held a pending one for. Text counts are now labelled TEXT; formatting suggestions are counted separately and disclosed on fetch as `cues.formatting_suggestions` with "this document is NOT settled", pointing at the Docs UI since they cannot be folded by tag.
3. **The NBSP diagnosis walked top-level paragraphs only**, so it was silent on a Word-imported TABLE — the shape most likely to carry the trap.
4. An *undesigned* SUGGEST refusal (Google rejecting the writeMode itself) surfaces with kind `unknown` and without the "nothing was written" wording. Recorded, not fixed: it is honest, just terser than the designed refusals.

Eleven mutation controls across the two rounds, every guard seen red before its green was trusted.

## For Claudes to come

**A guard placed after a return is not a guard.** `do_append` checked `suggest=` two lines below the branch that returns for `tab=`, so the one combination that most needed refusing was the one combination that skipped the check. It reads perfectly naturally in a diff, and no test caught it because the tests varied the dimension the guard was *about* (mimeType) rather than the dimensions around it. When you add a guard to a function with early returns, read the function top to bottom and ask which paths reach your line — the answer is rarely "all of them".

**Counting only what you can render makes you state false totals.** mise counted text suggestions, called the number "unresolved suggestions", and told a caller a document was settled while Google held a pending formatting change. The count was never wrong about what it measured; the *sentence* was wrong about what it meant. Where a count feeds a claim, name the population in the sentence — "3 TEXT suggestions" is a fact, "3 unresolved suggestions" was an error — and count the remainder separately even when you cannot act on it.

**The second time you re-implement a walk that already exists next door, it is not bad luck.** mise-jupuja's handoff wrote up a lesson banked in `tools/doc_chips.py` failing to reach a sibling module. This card then did it twice more: `_all_text` hand-walked paragraphs while `_iter_paragraphs` sat in the module it was already importing from, and the NBSP diagnosis went blind to tables as a result. The fix that generalises is mechanical, not attentional: **before writing any traversal of a third-party document model, grep for one that exists** — `grep -n "def _iter" extractors/` costs a second and would have caught all three.
