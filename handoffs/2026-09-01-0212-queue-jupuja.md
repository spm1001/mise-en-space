### Done — mise-jupuja (CLOSED)

`do(comment, file_id=…, content=…, anchor='slide 3')` now attaches the thread to that slide. `anchor='Sheet1!B12'` attaches it to that cell. `anchor='<some quoted text>'` attaches it to that text in a Doc. `to=` assigns it to someone. Commit `55fa9be`.

**The anchor spellings are the ones `comments.md` prints.** That is the whole design idea and it is worth keeping: mise-dukacu shipped a read side that renders `↳ slide 3 (Roadmap)` and `↳ Sheet1!B12`, and this write side accepts exactly those strings back. A Claude that has just read a deposit can quote a comment and reply beside it without translating between two vocabularies.

**The standing rule, and it is the opposite of the read side's:** a refused anchor is NEVER downgraded to an unanchored comment. The read side degrades quietly with a cue, because a missing locator costs information. The write side refuses loudly, because a comment on the wrong sentence costs trust — it reads as authored intent, and the human has no way to tell it was a machine's near-miss. Unknown slide, off-grid cell, missing quote, quote appearing twice, multi-tab Doc, preview refused: all refuse and name the unanchored fallback.

**The unanchored default now admits what it is.** This is the mise-mikawi residual, and it closes a real mystery: five comments posted during live work in August were reported as missing. They were never missing. Google treats an anchorless comment as one whose anchored text was deleted, files it in the comments panel under "Original content deleted", and shows it nowhere on the page. `cues.visibility` says so now, every time, and points at `anchor=`.

**Param budget.** One new param (`anchor`), and `to` reused rather than minting `assignee` — `do()`'s description gained the new grammar and came out with *more* headroom than it started with, 102 → 114 characters, paid for by compressing calendar detail that `mise://docs/do` already carries in full. The budget test is green with room to spare.

### Probe first, guess never

Twenty-four numbered exchanges in `docs/research/2026-09-01-jupuja-anchored-write/`, and every one of them changed the design:

- **`assigneeEmailAddress` rides inside `insertComment`** and is honoured (read back as `headPost.assigneeEmail`). It is also **completely unvalidated** — an address that cannot open the file is accepted and stored, with no error and no notification. Every assignment therefore carries a warning.
- **`writeControl.requiredRevisionId` guards Docs and Slides; Sheets accepts it and ignores it** (a bogus id returned 200). So the anti-race pin exists on two surfaces and cannot be faked on the third, which is disclosed rather than papered over.
- **A comment insert bumps the document revision**, so a pin is only good for the instant it was read.
- **The expensive one: `insertComment.range` is read in the `SUGGESTIONS_INLINE` index space.** The probe doc has open suggestions, so the two view modes disagree about where everything is. A comment aimed with clean-view indices landed on a completely different sentence, under a 200, with `plainTextQuote` as the only witness. Any future code computing a Docs range must use that view mode.

### The essayeur round — REFUTED, and it was right

Briefed narrowly on the falsifier's axis: *name an interaction that was not thought through*. It did. The implementation's ten-axis enumeration modelled a document as a flat list of sibling tabs holding paragraphs of plain BMP text, and a real Google Doc is none of those things. Seven findings, all fixed in the same commit:

1. **Docs indices count UTF-16 code units; the resolver counted Python code points.** One emoji earlier in the run slides the anchor. The sting: `tools/doc_chips.py` has `_utf16_len` precisely because an essayeur found this exact bug in mise-rubucu on 2026-08-24. The lesson was sitting in a sibling module and was not borrowed.
2. **`plainTextQuote` was named THE ORACLE in the research and then used as decoration** — displayed in a cue, compared against nothing. It is now compared against the aimed quote, so a mislanding from *any* cause, including causes nobody has thought of, arrives as `cues.landing_mismatch` naming the comment to delete.
3. **The field mask hid text inside tables.** A phrase appearing once in prose and once in a table counted as unique, so no ambiguity refusal fired and the comment anchored to the prose copy — with `plainTextQuote` echoing identical text, so even finding 2's fix could not have caught it.
4. **Tabs nest** (`Tab.childTabs`). The multi-tab refusal counted top-level tabs only, so the deliberate decline was vacuous against the shape real tabbed documents actually take.
5. **The Slides stale-revision retry re-resolved positionally.** A Docs quote is *content*-addressed, so re-resolving after a concurrent edit re-finds the caller's intent — that is why the retry exists. `'slide 2'` is *position*-addressed, and the retry fires precisely when the deck changed, so it could aim at a slide the caller never saw. The objectId is now pinned on the first pass and a deleted target refuses.
6. Anchoring to unaccepted suggested text is legal, lands, and is fragile — reject the suggestion and the thread orphans. Cued.
7. A transport failure reported "failed" when the outcome was genuinely unknown; a blind retry would double-post.

Thirteen mutation controls across the two rounds, every one seen red before its green was trusted.

## For Claudes to come

**A lesson banked in one module does not reach its sibling.** `tools/doc_chips.py` carries `_utf16_len` with a comment explaining that Docs indices count UTF-16 code units, written after an essayeur found emoji eating adjacent letters. Six days later a new module in the same repo computed Docs indices with `enumerate()` and shipped the identical bug — and it took another essayeur to find it. The fix that generalises is not "remember harder": it is that **when you write code computing an index, an offset or a length against a third-party API, grep the repo for the unit first.** One `grep -rn utf16` would have done it. The bug is invisible in every test whose fixture is ASCII, which is every fixture anyone writes by hand.

**A field mask is a claim about what exists.** Narrowing one is normally good hygiene — fewer bytes, clearer intent. Here every narrowing silently deleted part of the document from the resolver's view: `paragraph(...)` hid text inside tables, so a duplicate phrase counted as unique and the comment anchored to the wrong copy; omitting `childTabs` hid nested tabs, so a multi-tab guard passed a multi-tab document. Neither failed loudly, because a mask does not report what it withheld. Where a query feeds a *decision about uniqueness or completeness*, ask for everything and pay the bytes — the saving is real and the wrongness is silent.

**The oracle you identify during research has to become an assertion in the code, or it is decoration.** The probe notes for this card say, in as many words, that `plainTextQuote` is "the oracle for what the comment actually landed on" — and the shipped code put it in a cue and compared it to nothing. That is a specific and repeatable failure: the research phase finds the check that would catch everything, the build phase renders it as output, and nobody notices the assertion never happened. When a note calls something an oracle, the diff should contain a comparison.
