### Reflection

The card's `--how` offered two renders — UTC-with-Z, or the identity's Workspace zone named. UTC won on cost and comparability: the user's zone needs a Calendar `settings/timezone` call (a scope and a network hop the extractor layer must not make), and a thread mixing senders is then comparable line to line. The reader converts once. The loser is recorded in understanding.md so the argument does not come back as new.

The first suite launch died on `--timeout=600` (pytest-timeout is not installed here); the second ran clean. Neither was "the suite run twice" in the shared-box sense — the first exited in under a second.

## For Claudes to come

**A timestamp that agrees with its source to the second can still be wrong to the reader by hours — the zone is part of the value.** `parsedate_to_datetime` did its job; `internalDate` matched; the only fault was a render that printed the number without the frame. verification.md already names the writers stamping UTC+9 as `Z`; this is the mirror, a correct instant with no label. When a stamp crosses from an API into prose, the check is not "does it match the source?" but "could a reader in London, reading this bare, take it for something else?" If yes, the zone travels with the number or the number does not ship.

**`-q` in `addopts` plus `-q` on the command line is `-qq`, and `-qq` prints no verdict line.** Three thousand dots at [100%] with no `F` is real evidence, but you have to count characters to read it; the cheaper fix is to not add the flag the config already carries. Read `pyproject.toml`'s `addopts` before adding terse flags to a shared repo's test command.
