## For Claudes to come

**A staged programme's design note is its own ledger; read it against the artefacts before re-planning from a summary line.** The Workspace MCP Bench design note carries dated callouts at every stage it has passed — "Run 2026-08-17" under Tier 0, "Answered 2026-08-17" under the kill criterion, an amended Tier 0.5 gate — and the outcome card's `--how` is a dated chronicle beside it. A dispatch line written from memory three days earlier said three legs were left; the note and the board showed one. The failure is cheap to avoid and expensive to miss: re-planning from the summary would have re-measured two entrants whose gaps are structural and rebuilt a gate that had already been passed. Sequence for any programme with a design doc: the doc's own progress markers, then the card's `--how` tail, then the queue line — and where they disagree, the artefact wins.

**On this estate the marketplace's reassemble commits are the shipping oracle for anything vendored.** Each `Reassemble — <date>` commit in `spm1001/batterie` names, per plugin, the source SHA it vendored and the suite version it stamped. So "which version first carried commit X" is `git merge-base --is-ancestor X <vendored-sha>` over that log, oldest first — exact, marker-free, and independent of whatever versions a machine's plugin cache still holds. The `shipped_in()` function in this repo's CHANGELOG header is that loop — run it after `git -C ~/repos/spm1001/batterie fetch`, and note both `-C` flags are load-bearing: the first cut resolved the SHAs against the cwd, so from any other directory "not shipped" and "wrong directory" printed identically (cold-read catch, fixed the same evening). A post-assemble commit returning empty is its known-bad control, from this tree or any other now. Corollary already folded into CLAUDE.md: the repo's own CHANGELOG is not vendored (the assembler ships a generated stub), so it is an internal record and its headings should never claim a pending state that the daily assemble falsifies by itself.
