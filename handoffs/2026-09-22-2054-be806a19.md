## For Claudes to come

**A blank-slate spawn is bare only if its working directory is outside the user's home.** Claude Code resolves project configuration by walking up from the cwd, and on a machine whose user config dir is `~/.claude`, that directory is an ancestor of every path under home — so a sandboxed HOME, `env -i`, and a fresh credentials file leave the settings hooks, the user skills and the rules shards loading exactly as they do in a normal session. The tell is in the stream-json `init` event: user skill names in `slash_commands`, and any `hook_started` before `init`. Measured 2026-09-22 with a one-variable test (same spawn, world under `~/scratch` versus `/var/tmp`), and confirmed retroactively on the 17 Aug routing-obedience transcripts, whose "no CLAUDE.md, no skills, no hooks" condition had `consult` and `macos-fluency` in every init event. Any past or future "naive Claude" measurement on this estate should be checked against that tell before its baseline is believed.

**In an agent experiment the written answer is the artefact and the stdout stream is not the record.** (Glossary for the pilot's cost columns, used above and in the tally: A = tokens crossing the MCP tool boundary, B = A plus every deposit the agent then read, i.e. cost to completion, C = the model's billed input; "DPP term iv" is the Google Developer Preview clause that keeps Google-side numbers out of public repos; §7.1/§8.1 are sections of the bench design note in notes.) `claude -p --output-format stream-json` stopped mid-run on 4 of 40 fifty-to-hundred-second spawns that completed, wrote their answer file and exited 0; a token counter reading the stream printed a plausible zero for a run that had made three MCP calls. Score recall from the file the agent was told to write, count cost from the transcript Claude Code keeps in the (sandbox) HOME — copy it out before any cleanup trap — and treat a stream with no `result` event as "cost unknown", never as a small number. A control that proves the fallback matches the intact stream on a known-good run (it did, exactly, on A/B/C) is what earns the fallback its trust.

**Share a test corpus to the caller, not to the world.** Under an anyone-with-link grant, Google's Drive search from the ITV caller could not see the planetmodha corpus at all — folder listing and title search both returned empty — because a file is outside a caller's search corpus until that caller has opened it, the same mechanism mise-jefaki found from mise's side. A direct `type=user` grant to the caller's account put the files in its corpus first call, needed no public window, and revoked cleanly. Where a role matters (Drive comments under Google's server needed commenter, not reader), the grant is part of the experimental condition and belongs in the pre-registration.
