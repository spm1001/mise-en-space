## For Claudes to come

**A token carries its own client, and that one fact made re-consent-free migration possible.** Google's installed-app `token.json` holds `client_id` and `client_secret`, so refreshing never consults the client file; the client file matters only at consent. That made `client_id` the natural identity key for the whole seam: adopt only the pre-seam token minted by the configured client (each flavour's old store holds a different Workspace), and refuse a store holding another client's token.

**Two general moves came out of this work.**
- **Check the name before shipping any new environment variable.** `MISE_` is jdx/mise's namespace: it declares 302 variables, and `MISE_DATA_DIR` is its documented data-dir override. Check a new name against the namespace owner's settings list, one curl and one grep, before it ships. Prefix mise-en-space's own variables `MISE_EN_SPACE_`.
- **Treat every new "look in the old place" fallback as a door for the developer's real state into the unit suite.** Pin it in conftest the day it is written; the mutation control that caught this one was aimed somewhere else.

**The throwaway-home proof in `docs/research/2026-09-27-nujina-seam-proof/` is reusable** for any credential-path change. It works like this:
- a claude-vanilla world outside `$HOME`;
- the engine copy with its client removed;
- real tokens copied into the world's old locations;
- every server spawned through `env -i` with only the wiring;
- then a real `claude-vanilla -p` run as the product-surface check.

It proves "no re-consent" without anyone clicking a consent screen.
